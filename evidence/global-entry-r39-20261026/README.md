# R39：受控 Codex 技能清单、详情与选用

旧受控代理将 skills/list 固定回复为空数组，使真实技能页显示“找不到技能”。本版使用固定原生程序解析当前 SKILL.md 快照，返回原安装路径与错误；不自动执行正文或给模型签发阅读凭证。

## 怎么查看

在 Codex-Controlled 按 Ctrl+K，输入“技能”，选择“前往技能”。本机实际显示74个不同名称（77个来源条目，三个同名条目由客户端合并），可打开正文详情、点击“立即试用”。聊天输入框输入 $find，可搜索并选中 Find Skills。设置搜索框不是本版本客户端的技能列表入口。

## 查出的反例与修复

独立审查在R38候选中实际复现：把技能提示拼入原始用户文本会吞掉 /workflow pause；该候选未部署。R39将提示放到独立untrusted上下文，用户原文单独用于控制与授权。原生回归覆盖五类命令的两种条目顺序；独立审查另跑四条真实controller全流程，实际选择、写入校验、接受、状态和暂停均通过。

当前清单经实际原生解析，无账号复制；改名后刷新、旧名称拒绝、无效YAML报错、硬链接和junction邻例也已验证。发行及个人目录中的两份Skill没有改字：已有stage-checks规则已要求真实UI、冷执行和原始授权隔离，本轮以具体接线和可执行回归落实，避免重复堆文字。

## 边界

本轮验查看、读详情、搜索和选用；不声称开关、卸载、新建等技能写入按钮已验收。清单是当前受控入口配置的个人/发行/托管根，不把任意plugin缓存算已安装。客户端实际把技能chip序列化为Markdown文本；结构化Skill输入另由真实原生测试覆盖，不冒称UI发送了该结构。独立审查没有另做GUI或付费模型复现。

DSH生产代码及两份Skill未改变，DSH包同步当前来源，未新增付费DSH模型验收；历史DSH实测保留原来源身份。包不含私有Codex桌面。
