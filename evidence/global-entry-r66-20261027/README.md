# R66 · 账号模型目录、原生 Ultra 与既有对话恢复

旧受控目录冻结在安装时快照，并主动剥掉 Ultra。现在每次受控 Codex 启动都通过已安装的官方原生 CLI，在临时隔离目录使用现有账号执行 initialize/model/list；不发送推理任务。核对原生返回与本次新缓存的一致性后，再保留受控工具限制。失败时保留已验证的 owner 目录并记录 fallback，不伪造型号。现有原生启动器丢弃子进程 stdout 正文，因此本次以实际生成目录的 fetched_at 和 RPC 读回证明刷新，没有把未观测到的启动日志当作证据。

Ultra 只对真实元数据声明支持的 v2 型号开放，保留原生委派机制。子代理只能由当前后端关联的父线程/回合活动绑定；工作区、任务控制器与门禁继承父任务。无历史子代理保持原生无项目工具的限制，不能因此开放原始终端或写入。子代理完成不代替整体交付或用户验收。

既有受控历史曾把 additional_tools 清成空数组，并保留 disabled 协作标记，导致新会话可用而旧会话缺工具。现在仅规范化私有副本的旧声明和最后一个上下文的能力标记；先预检、备份，再原子更新字节偏移及历史数据库。保留用户消息、线程身份、历史 ordinal、项目绑定和当前任务控制器。真实原生分页 API 比对、冷恢复以及提交失败后的双重回滚均有回归。原版历史不作为此规范化的目标。

复审还发现恢复期间关闭 gateway 可能遗留新后台进程。最终版本在关闭旧进程后和新进程建立后均核对关闭状态；关闭期间建立的进程立即回收。Windows 设置的后台重启也使用相同方法。

## 原版 Codex 的区别

原版配置还指向一个旧 model_catalog_json，自定义文件只为了把 Sol 上下文从 272000 提至 500000；当前账号目录已原生支持 500000。已备份并只移除这条过期覆盖。隔离原生实验确认：更换目录文件、移除配置及 reloadUserConfig 都不会热刷新运行中后台的模型表。因此承载当前任务的原版应用需要退出重开一次；没有声称当前未重启窗口已经出现 Terra。

本地只更新受控 Codex 的来源/校验 pins、包装和原生启动器。原版进程、DSH 服务、账号来源、依赖树、私有桌面、原有权限和状态路径保持。默认模型偏好恢复为测试前值。两份 Skill 的阶段参考均已同步并读回。

DSH 日常继续使用现有受控 Web 入口；本次未替换其运行代码或迁移机器人。独立 DSH 下载包包含相同源码及 Skill 参考，但不包含账号、密钥、运行状态、Node/SDK 或私有 Codex 桌面。

官方型号说明：[GPT-6.1 Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra)。实际可用型号以各账号的原生目录返回为准，不能把作者的账号列表当成所有用户的授权。
