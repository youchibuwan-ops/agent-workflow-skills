# R50 · 当前项目发现、正常只读回复与测试额度边界

本版修复受控入口“知道项目已选中，却不会自行发现目录和读取文件”的缺口。
Codex 和 DSH 共用目录分页能力，沿用原来的 15 个工具 schema，兼容旧受控历史。
DSH 目录读取仍经过原生权限服务；中文目录名使用 ASCII JSON 转义传输。
根目录替换、越界链接、原生拒绝和停止点均不能降级为无约束文件访问。

这些是作者复现结果，不冒称独立审阅者复现了全部项目。

  完整读取三个当前文件；新进程恢复同一会话后重读改变的字节。两轮原生状态均为 `completed`。
- [DSH 真实模型](dsh-model.json)：官方 DeepSeek 提供器、生产工厂和原生权限服务，
  自动搜索、发现并完整读取未知项目，输入未修改，原生回复正常结束。
- [实际项目](actual-project.json)：本机已安装入口恢复原有 R39 测试对话，
  从已选项目自行发现并完整读取说明、引擎配置、启动场景；按原始字节范围及 SHA-256 核验。
  原游戏文件未修改。模型输入由技术 RPC 驱动发送，桌面导航及可见结果另行观察，
  不冒称通过 UI 输入框发送了这轮请求。
- 正常配置、Windows 设置就绪状态、原生文件读取和 Skill 清单接口分别核验。
  原 R36/R37/R39 的设置、添加项目、模型选择及 Skill 界面证据保留各自来源身份；
  本版没有声称把所有桌面控件重新操作了一遍。

明确只读且已取得当前搜索和文件证据的诊断可以正常回复，业务仍为
`pending / complete=false`。这不会授予制作、写入或阶段跳转权限。
冷恢复保存已签名的当前只读意图，不从混合历史重新猜测；引用文字和冲突修改要求不能授权。

## 安装与复核

从 [R50 发行页](https://github.com/youchibuwan-ops/agent-workflow-skills/releases/tag/v0.2.0-host-preview.3-r50)
下载 ZIP，完整解压后运行 `安装DSH.cmd`。随后在自己的 PowerShell 设置自己的
`DEEPSEEK_API_KEY`，进入实际项目目录，运行受控入口：

```powershell
& "$env:USERPROFILE\.agent-workflow\global\dsh.cmd" web
```

打开入口打印的本机网址，在 Web 中添加并选择实际项目工作区，再提交任务。
终端 `cd` 本身不保证 Web 选择了同一目录。Web 支持连续选择、修改和反馈；
`headless` 一次提示后退出，不能当作完整多轮界面。
只有明确需要让终端 `dsh` 别名指向该入口时才运行 `启用默认DSH.cmd`。
原环境仍独立存在；安装不会让其他应用里的对话自动迁移。

源码、证据文件和可选 ZIP 的一致性可复核：

```sh
node evidence/global-entry-r50-20261026/verify-evidence.mjs
node evidence/global-entry-r50-20261026/verify-evidence.mjs --package /absolute/path/to/the-r50.zip
```

这检查当前字节与发布者记录是否一致，不重演付费模型历史，也不是第三方数字签名。
