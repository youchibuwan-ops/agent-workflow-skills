# R56 · 正常桌面管理与受控执行分流

本版修复共同路由边界：聊天和项目的原生管理请求进入统一管理通道，模型任务仍进入受控工具与流程门禁。撤掉被替代的项目、归属和队列零散处理。R50—R55 是保留的候选记录，不冒称这些版本已公开发行或完成全部桌面验收。当前作者回归 573/573，零失败、零跳过；真实模型、实际界面和未覆盖项分别记录。

## 独立审阅与保留反例

[原始 R51 独立审阅](INDEPENDENT-REVIEW.md) 的结论是 **No — one fix pass**，独立跑了 46 项但仍找到三个 Important 问题。本版由作者修复并新增反例回归；没有让审阅者对 R56 再投通过票，也没有改写旧结论。

后续新增边界另有两份独立复审：[私有客户端能力](PRIVATE-CAPABILITY-REVIEW.md) 独立复现 55 项及真实 vendor 方法/字节探针，[查询修正](SOURCE-QUERY-REVIEW.md) 独立复现 17 项及三个相邻分支探针，均无 Critical/Important。它们各自声明范围，不冒称独立跑过全部 573 项、付费模型或 GUI。

三个反例是：跨项目修改标签成功后全网关退出；归档进行中另一个客户端启动模型回合；删除尚未生效时杀死宿主，却留下最终删除标记。分别以原生持久聊天、跨客户端延迟夹具、删除生效前后真实子进程强杀与冷恢复验证。

实际桌面还揭示归档页依赖 `externalAgentConfig/import/readHistories`，打开聊天会请求 `thread/attachment/list`。它们属于只读元数据管理；本版按原生参数和结果核验，未知参数、外来聊天、隐藏执行参数以及相邻导入/附件写入接口继续拒绝。没有把“临时聊天能归档”当成整个页面没有异步失败。

R53 又暴露了另一个边界问题：为读附件索引先迁移全文，会让大历史触发正文迁移预算。R56 只读元数据索引，实际原生 125 条附件验证了默认 25 条、顺序和游标；原始记录与当前私有记录正确合并，超量、错误 JSON 和跨聊天游标拒绝。尚未迁入的聊天删除，只提交受控视图的真实隐藏效果并通知其他窗口；原始聊天保留，没有复制全文再删除。正在等待工作区核验的模型回合不能在该视图删除后继续迁入。

R54 的“本地过滤后无错误”观察已撤回：延迟检查仍会出现未接入的 durable 来源错误。R56 将界面来源与实际注册的 local 通道对齐；真实冷启动后的“全部聊天”和“本地”整页均完成加载，没有该错误。主进程的 Local Work 备用执行器走原生 disabled/stop 路径；从当前进程启动起的实际日志中未再启动或重启它。两份界面资源及主进程边界按固定输入/输出字节核验，旧私有构建被拒绝，官方原始文件未改。

当前实际界面另完成临时聊天重命名、置顶、归档与恢复；删除由技术原生 RPC 在同一临时记录上完成，界面最终永久删除按钮没有点击。完整新建项目流程为命名 → 添加源文件夹 → 系统目录选择 → 信任 → 创建；项目实际出现在侧边栏后再通过界面移除，文件保持原样。起初把“打开文件夹”当作“创建项目”的作者测试判断错误已保留，没有为该误判修改源码。原用户聊天未删除。

R53 首轮全量检查有一项公开来源测试收到 GitHub HTTP 403；实际匿名 API 额度为 0，联网和有授权的 GitHub 连接仍工作。原报告与后续重验分别保留，不能称为整机断网或把首次失败改写为通过。最终计数以 summary 中的当前完整运行和独立保留字段为准。

R55 首轮全量为 506/507：GitHub 把未加引号的 find-skills 拆成宽泛关键词，返回 1,200,291 个结果，前三仓库均无匹配路径。这次不是断网。R56 先查完整短语的仓库名，确无匹配树才扩到描述/README；获取后的固定 commit、Git blob 与许可证检查不变。真实排序中出现的无许可证副本仍为 incomplete，不把第一个搜索结果当作必定可用的能力。

R56 Codex 新会话和同聊天冷恢复两轮均 completed，12 次真实工具调用；DSH 官方提供器 49 次真实工具调用后通过。两者自行发现未知文件名的项目、搜索 Skill 并核实际文件。R54 的冷恢复/反馈器失败另行保留：不能把旧失败倒签成当前，也不能把当前通过说成所有历史尝试均通过。当前只读回复准入仍是保守规则，不证明任意自然问句都能无额外阶段回答。

当前配置页仍有两条兼容告警：旧全文历史读取接口、废弃的 codex_hooks 字段。没有隐藏或声称已修复这些告警；当前实际配置已核 hooks=false，同时保留旧别名。原生执行器的 read-only 与 web_search=disabled 保留；受控公开来源检索和获准文件写入走独立工具。云端、插件与外部导入等未接入能力可能产生拒绝诊断，不在本次正常本地管理验收范围。

## 安装

从 [GitHub Releases](https://github.com/youchibuwan-ops/agent-workflow-skills/releases) 下载当前 R56 ZIP，完整解压后运行 `安装DSH.cmd`。首次需联网下载官方运行时及锁定依赖。包不含私有 Codex 桌面或凭据；升级保留旧版本备份。

在自己的 PowerShell 设置自己的 `DEEPSEEK_API_KEY`，再运行：

```powershell
& "$env:USERPROFILE\.agent-workflow\global\dsh.cmd" web
```

打开打印出的本机网址，**在 Web 中添加并选择实际项目工作区**，核对名称后提交任务。仅在终端 `cd` 不会替 Web 选择工作区。需要替换正常终端的 `dsh` 命令时，另运行包内 `启用默认DSH.cmd`。这不会把其他既有 Harness、QQ 机器人或普通 Codex 入口自动改成受控入口。

本机 Codex 使用现有 `Codex-Controlled` 快捷方式。旧聊天恢复后的模型回合和从该入口建立的新聊天都进入该宿主；原始普通 Codex 入口、云端/SSH/WSL 和未接入插件不在此覆盖范围。

## 边界

只复制 SKILL.md 仍是 `instruction_only`。本记录没有证明任意 Skill 的语义质量、审美质量或全部未来桌面功能；未重新做完整七阶段创作任务或 DSH 桌面 GUI。正文迁移到模型会话仍有独立的 64 MiB 与行数准入边界，元数据读取或删除通过不证明任意大旧历史都能恢复为模型任务。原生只读回合可以正常结束，业务流程仍为待完成状态，不能借正常回合结束解锁制作写入。云端执行、插件执行、附件写入和外部配置导入没有因此开放。
