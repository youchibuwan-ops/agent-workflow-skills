# R73 · 冷恢复复核与 token 消耗

一次真实会话的同一方向微调不应每次重新展开研究。宿主在研究完整送达、逐项确认、选定方案后，把可复核的摘要和真实选择写进现有签名会话记录；不保存或重放一次性正文回执。冷恢复时宿主本身重新寻找该 Skill、比对来源与已安装文件的完整清单及哈希，并重新获取参考原文、核对当前字节。全部一致才重建研究阶段证据及原选择；材料变化、未确认、网络不可用或记录不存在时仍退回发现阶段，旧回执和未选方案不放行。项目文件仍通过当前原生权限读取，修改后必须重新验证当前产物并等待实际反馈。

正常空闲退出与明确暂停、取消和失败分开：空闲关闭后可恢复原任务，主动暂停或取消仍要求原有外部恢复授权；授权后才能检查已保存摘要是否仍可用。旧提示曾在研究已保留时仍要求搜索当前 revision，现按宿主实际状态显示，并在修改阶段省去无关的发现说明。

## 真实模型对照

同一项双语通知的单行微调，使用隔离测试工作区、同一 Skill、两份相同的前置 RFC 参考、同一外部修改指令、DeepSeek Flash 官方提供商和实际 DSH SDK `session/resume`。旧版重查时可以选择其他参考。测试驱动先完成并确认研究、选择方案与初稿；原生会话在此之前创建，但不含既往模型消息。因此这是受控的冷恢复场景，并不代表长对话上下文或所有项目。测试驱动的选择和确认不是用户审美验收。

首次设计的对照只预建宿主记录，未创建并恢复原生 DSH 会话，所得两组数据全部作废，未计入上表。修正后的对照先创建并持久化原生会话，再调用 `session/resume`；不能把作废结果称为节省。

## 验证和边界

- 工作流、恢复与上下文投影相关测试：169 项，168 通过、1 项 OS 隔离执行集成因未配置测试环境而跳过；实际 DSH SDK 的空闲退出、取消、原有暂停授权和字节保护针对性测试 5/5 通过。打包测试 6/6，DSH Skill 分发 5/5，两个 Skill 元数据校验通过。
- 本地 R73 受控 DSH 安装读回通过；使用已安装的入口配置启动隔离原生 dry run，第一条模型请求在提供商调用前停止，0 次付费调用，发行源码未改变。
- 最终 R73 与实测 R71 的运行差异只有已获真实授权的用户暂停后允许重验研究的一条条件；该分支有针对性测试。其余两个差异是对应测试和两份 Skill 参考文字；核心恢复、原生 DSH 接入与模型工具代码字节相同。模型数字是 R71 的实际值，不冒称重新调用了 R73。
- 当前自动复用支持一个已采用的 Skill、至少两份可重新获取且字节不变的 HTTPS 文本参考。其他情况保守回退；升级前会话没有签名研究摘要，首次冷恢复仍需补核一次。直接恢复后立即验收旧草稿未在此模型对照中验证。
- 本地 DSH 安装仅更新受控入口、controller 配置和两份个人 Skill 参考；运行时、账号、原 DSH/QQ 机器人配置、工作区及历史不迁移。已经运行的 DSH 进程需要退出重开才加载新版本。
- 原始材料、未确认正文、错误、审计记录及权限检查保留；没有修改日常模型输出上限。每次测试回复上限为用户指定的 100,000 token。
