# R62 · 连续任务与上下文修复

同一个目标贯穿多条消息。解释方案、选择方案、普通追问和稿件细节反馈续接当前阶段；不再把每条消息或内部 Agent 更换当作新任务。

## 当前行为

- 研究完成才登记方案；方案已经公布时解释原选项，用户选中后直接制作。
- 普通问题保留阶段；同方案细节修改保留已核来源、方法和选择，只重开制作与当前产物验证。明确取消方案、换方向及独立新目标仍撤回原选择。
- 活跃会话内部 Agent 更换时保留任务，并重绑新的原生权限执行器。新格式的签名恢复记录保留真实用户选择；冷启动重新核当前来源事实，不恢复过期读回执。
- Codex、DSH 的模型工具结果去除重复完整状态，实际 data、错误、确认挑战和完整状态查询仍保留。DSH 已送达旧状态通过原生追加式日志替换压缩，原记录不改；待送达字节仍逐字校验。
- Codex 撤销适配器强加的三个禁用自动压缩设置，保留原生/用户默认；关联线程、回合和未确认来源仍受门禁检查。

更新了两版 Skill 的任务边界及阶段检查要求。宿主状态决定当前阶段，模型不用每次重读入口 Skill 或重复填七套状态表。

每次测试模型回复的上限是用户指定的 100000 token；这不是日常 DSH 对话限制，也不是整轮累计 token 上限。
