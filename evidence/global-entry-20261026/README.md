# 默认受控入口：作者本机验收记录

本目录记录 2026-10-26 Windows x64 本机测试。它是作者自测及只读复核，不是同学独立复现，也没有公开可验证的第三方运行签名。原始会话、工具返回、认证与本机路径保留在私有证据目录；公开记录只含测试输入、产物、版本、结果和字节摘要。

准确结果见 [summary.json](summary.json)，冻结发行文件见 [payload-manifest.json](payload-manifest.json)。源码清单 SHA256 绑定具体安装包；不能把旧 preview1 或失败的 R04 运行换个哈希后当成本版证据。

真实模型任务要求读取 BOM/CRLF 输入、实际查找及完整核读测试 Skill/MIT 许可和两份 RFC、先给方案、等待外部选择、生成当前双语通知、校验并等待外部反馈，最后交付和学习。提前写入必须真实被拒绝。结构校验与任务事实检查分开；保留原文件的所有字节。

这两个 fixture 是封闭的文本任务，结果不能推广为任意艺术、事实核查、软件工程或自动 Skill 更新能力。模型完成时的 `no_increment` 仅适用于已有测试方法没有已验证新增量；它不是本维护任务无需总结的理由。

## 保留的失败

- R04 DSH：实际提供器流调用 22 次后，测试器累计 JSON 字节上限触发，真实 native aborted；不是模型拒绝写初稿。随后修复测试器诊断，以及原生取消后宿主仍显示旧轮阶段的问题。
- R04 Codex：32 次受控工具调用、两轮任务后，被未约定的英文标题/字数门槛误判。旧失败保留，评分器以真实合法原稿和失败邻例校准后才重新跑完整链。
- R05 DSH：20 次提供器流调用后已到真实反馈阶段，评分器误要求编码说明必须进入产物；说明实际已在本轮可见回复中。但新文件 LF 与所选方案承诺的 CRLF 确有差异，仍需真实修订。原工具参数就是 LF，不能归咎于工具。旧探针终止进程的失败记录保留，后续探针须允许在同一会话反馈、修订和复验。
- R06 DSH：44 次提供器流调用，已实际反馈、重新核读和再次选择；旧单次回复上限 4096 触发 `max-tokens`，旧探针又将可恢复状态当致命失败。后续按用户明确的每次回复 100,000 上限执行，并以真实当前阶段继续，而非冒充通过或丢弃全场。合法双语标签字段/共享邮箱与真实字节格式分别校验；字面反斜杠 `\\r\\n` 不是真 CRLF。
- 更早 R01：免费首请求检查在不存在的未来私有目录上失败，没有调用提供商；修复路径防护后重新免费预检。
- 旧 R04 全量测试：165/170 及五项 runner 环境失败原样保留；五项修正环境后精确重放通过。本版全量结果独立记录，不把两次旧运行拼成一轮全绿。

## 完整性与学习

每次启动先验证完整发行源码和安装后依赖树；实际受控 npm 安装、包/锁文件及完整官方 Node 工具树构成首次信任依据。依赖后改、增文件和不可信旧目录均拒绝。HMAC 认证本机所有者记录，不是公开供应链或作者行为的第三方签名；发布 ZIP 的 SHA256 仍需从可信发布处核对。

本轮已实际维护两版 Skill 的 [阶段检查](../../skills/proactive-skill-discovery/references/stage-checks.md)：普通入口与测试入口分开验收、完整依赖树、Windows 文件别名及 MSIX 路径、结构化原生结果、足额测试预算及评分器校准。对应边界、失败反例和当前行为回归实际执行；个人目录安装需逐文件读回核对。没有新增无关 Skill。
