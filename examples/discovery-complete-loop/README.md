# 从制作需求到可复用 Skill：使用示例

本页是使用流程说明，不是已完成的游戏效果或模型效果对照实验。
涉及的真实参考、候选差异、作品和验收结果必须由实际任务产生，不能照抄一份虚构结论。
可执行的真实维护夹具见[相邻示例](../discovery-maintenance-loop/README.md)。

## 1. 用户提出任务

```text
使用 proactive-skill-discovery，给游戏制作低频音波攻击效果。
先主动找专业 Skill 和多个相关游戏中的同类元素，给我清晰的参考与方案比较，
让我先选方向，再制作初稿。根据我的反馈调整，完成后总结并维护或制作 Skill。
保留既定的伤害、速度、寿命、双向贴地穿透，不提前接入正式游戏。
```

## 2. 主动研究并给出多个方案

执行者自行拆出发射、传播、命中、目标受击、消退等环节，研究对应 Skill、
实际游戏案例和专业制作方法。查看能判断细节的完整动态，记录来源、版本、
许可及适用条件；不能等用户指出受击反馈才补查。

给用户通常3—5个有真实材料支撑的方案，每个都包括：

- 原始视频、图片或可实际查看的材料及查看范围。
- 借鉴的具体机制、与其他方案的区别。
- 如何适配本游戏的画风和既定规则，以及尚不能确定的部分。
- 推荐理由；由用户先选，作者推荐不等于用户选定。

这些是相关实例和方案，不是擅自批量制作多套成品。用户说“像某个游戏”是研究线索，
不是只允许找那一个参考，也不授权直接复制素材。

## 3. 按选定方向初步完成

实际安装并采用能补足能力的 Skill，用当前输入验证方法，再完成可看的初稿。
交付当前动态、原尺寸与必要放大检查，以及规则未变的适当验证。
“找到了 Skill”“画面能显示”或“代理通过”均不能代替这个产物。

## 4. 根据反馈调节

把反馈拆成可检查的差异。例如用户认为命中缺乏冲击，应核查完整受击过程，
补查对应方法后调整局部与时序，再检查整段攻击和受影响保留项。
已认可的部分保留；未完成的点继续处理，不把一次截图修改称彻底完成。

## 5. 完整交付并沉淀

完成原要求与确认后的反馈，交付正确版本与检查结果。总结本次何种方法在何种条件下
有效、如何验证、何时不适用；优先修订已有同类 Skill，无合适归属且能独立复用时，
实际制作、验证并安装新 Skill。给出修改位置和证据，不只写“下次认真”。

软件、分析、文档等任务同样按其产物应用这套闭环：主动研究相关方法和材料，
对实质未决方向先选方案，再应用、反馈、验证和沉淀。
