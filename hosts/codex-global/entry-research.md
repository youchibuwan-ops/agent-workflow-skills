# Private entry feasibility: observed facts and remaining acceptance

See entry-research.json for exact installed paths, offsets and hashes. This is a read-only inspection plus a pure patch transform. No application executable, ASAR or global configuration was modified, and no second app instance was launched.

The actual runtime is Owl, with the Electron-compatible fuse sentinel inside chrome.dll, not the tiny Codex.exe launcher. Its nine-bit v1 wire is 010011001. Node options, main-process inspector and run-as-node are disabled. Embedded ASAR integrity and only-load-ASAR are enabled. Thus an environment preload, inspector injection, or a loose resources/app directory is not an available entry mechanism. This interpretation follows the official [fuse specification](https://www.electronjs.org/docs/latest/tutorial/fuses).

ChatGPT.exe has an existing ElectronAsar integrity JSON resource. Its SHA256 value exactly matches the original raw ASAR JSON header. [Official integrity documentation](https://www.electronjs.org/docs/latest/tutorial/asar-integrity) specifies that Windows stores this header digest in the executable's Integrity/ElectronAsar resource; mismatch terminates the app. Changing a file's block hashes in the ASAR header alone cannot work with the stock PE resource.

The minimal planned private installation shares unchanged large runtime files and assets without writes, copies only the small PE, and streams one private ASAR (about 640MB). Replace the uniquely anchored main transport factory at its beginning using entry-patch.mjs. Its insertion rejects SSH, durable, WSL, remote-control and unknown host IDs before constructing transports, and directly returns the native websocket transport for local with the wrapper's opaque loopback URL. The original branches remain unreachable; FORCE_CLI and host websocket configuration cannot select a fallback. Recalculate file/block integrity, header digest and only the private PE resource. Keep the stock integrity fuse enabled. This private modified PE loses its vendor signature; do not label it an official signed build. Whether this runtime/Windows execution policy accepts the private layout is still unverified.

The transform's tests execute fixture transport construction and assert zero unsupported connections, fixed-hash rejection and no original transport fallback. They do not prove a private desktop launched. The root implementation owns ASAR rebuilding and final isolated UI acceptance. A connection-before guard at this app-server factory does not by itself prove every non-app-server cloud API is blocked; inspect any direct task-creation HTTP routes before claiming all desktop actions are covered.
