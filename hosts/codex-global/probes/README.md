# Codex 真实模型独立技术探针

`real-model.mjs` 使用正式 owner 安装预检、生产 gateway 与 generic factory，经真实 Codex 0.164 WebSocket 协议测试普通双语通知任务。它不启动桌面 UI，不代表人工审美验收或日常所有聊天已验收。

默认或 `--dry-run` 只做完整性检查、真实后端 initialize 与 thread/start，不发送模型 turn。付费执行必须显式 `--run --approved-source-manifest <精确获准 SHA256>`；探针自身也必须属于同一已批准 manifest，r01 永远被拒绝。不要修改 immutable release，或替换旧证据中的源码 SHA 来适配新探针。

## 完整流程的余量与停止条件

读取并确认两份完整 RFC、Skill 与许可证、观察参考、展示方案、写稿、验证及学习需要多个真实工具回合。当前探针留出 160 次受控 dispatch、每轮 20 分钟、最多 6 轮与累计 32 MiB 证据捕获余量；这些是异常保护上限，不是要求消耗完的目标。正常 driver 仍只发送任务、实际选择、实际接受三轮，完整通过立即停止，不为用满上限追加调用。

单次 WS 帧仍受原有 8 MiB 解析边界约束，生产 gateway 的完整工具结果边界也不改变。超限仍关闭连接和后端，清除临时凭据，保留失败。该技术通道无法精确统计 HTTP 模型请求数或金额，因此不把 dispatch/turn 上限说成精确请求或费用预算。

driver 只在收到真实 options 卡后选择；只在当前产物通过独立事实、基本英文及 UTF-8 检查后接受。原始 BOM/CRLF 输入保持不变，挑战确认、提前写入拒绝、七个宿主阶段卡及完整 native 工具返回逐字对照均保留。验收标准不随预算放宽。

独立通知核验按原始“简短、自然中英通知”目标标定：不强制 `English/英文` 标签，也不要求额外凑满 25 个英文单词；事件名可作标题。它要求清楚独立的英文句段或自然祈使通知表达，英文事实可定位，日期/时段正确、无乱码；中文中的英文关键词与纯关键词列表不能替代英文通知。句段识别只是保守结构 heuristic，不能认证一般语言质量或审美。原 R04 真实原稿因未约定标签/字数被旧评分器拒绝的记录完整保留，不回写成旧标准通过；新评分器由该实际正样本与缺事实、掺中文、关键词列表、坏 UTF-8 邻例做纯测试验证。

## 版本与证据

冻结 R04 的旧探针保留原 45 dispatch / 180 秒每轮 / 3 轮 / 8 MiB 上限；工作树本次仅改变独立探针和单测，不追改 R04 或正在运行的旧实例。旧运行按旧源码和实际旧上限报告；即使旧上限足够并通过，也不能称它已验证新上限。

新探针的成功和失败结果都记录实际 `limits`、`probeSourceSha256` 以及已验证的 `sourceManifestSha256`，避免把探针版本与宿主版本混为一谈。既有真实运行证据不会因本次纯单测改变，新增付费运行仍需独立授权。

纯单测命令：`node --test hosts/codex-global/probes/real-model.test.mjs`。这不调用真实 provider，也不替代真实模型、桌面消息输入或人工审美验收。
