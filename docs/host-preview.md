# Codex / DSH 受控入口测试包

本预览用于让使用者实际测试工具拒绝、来源送达、阶段顺序和独立产物验证。
普通 Skill 安装仍为 `instruction_only`。本包提供独立受控 CLI，不替换当前 Codex 桌面，
也不将所有任务、所有工具或所有质量要求宣称为已经接入。

## 安装与测试

完整解压发布 ZIP，核对发布页整包 SHA256，然后双击 `安装.cmd`。
安装目录为个人 `AppData/Local/AgentWorkflowPreview`；既有桌面配置和普通 DSH profile 保留。
没有可调用的 Node ≥24.9 时，从官方固定版本下载并核对 ZIP SHA256。
依赖按锁文件安装；相同锁版本共享一份 SDK，不为每个实验复制完整运行环境。

双击 `Codex测试.cmd` 或 `DSH测试.cmd`，先运行零模型预检。
只有使用者明确输入 `RUN` 才启动真实模型任务。Codex 使用本人已有的精确支持版本、
模型目录和登录；DSH 从本机 `DEEPSEEK_API_KEY` 环境变量取凭据。
包内没有维护者账号和原始私人测试日志。测试后用 `导出报告.cmd` 导出脱敏状态与计数。

## 真实门禁边界

- Codex 使用固定版本 app-server、仅含工作流工具的模型工具目录和 WS 代理。
  代理持有所有动态工具回调；原始 shell、补丁、任意转发和未知工具不交给模型。
  桌面会话恢复等日常兼容性没有因此通过验收。
- DSH 使用 root-owned 原生 guard、精确 Tool 定义身份核对和受控启动器。
  插件卸载、同名子作用域工具、内部转发及 guard 故障不能恢复原始工具。
- 同一模型回复预排多个工具不等于读取结果已送到后续模型请求。
  每段正文返回不可预测的一次性挑战，下一次收到结果后才能批量确认；未确认不能审核。
  还检查最终原生工具结果未被摘要或溢出文件替换。确认不证明理解或事实判断正确。
- 宿主根据真实回执自动生成有序阶段报告，免去模型重复填写七份 JSON。
  方案未选、反馈未处理、产物未独立验证、经验维护未落实时仍停在相应阶段。
  未展示/无效选项、提前接受尚不存在的初稿，均不产生授权。
- 验证器不能把未覆盖的需求标为通过；冻结标准答案不作为模型提示的一部分。
  反馈要求修改时重开初稿阶段，原验证和接受记录失效。

## 当前可测试范围

内置题每次生成不同输入，要求只写 `output.json`，独立重算当前 generation、总和和
原始字节 SHA256。来源是明确标注的本地控制夹具，用于门禁回归，不冒充专业 Skill 搜索。

自备任务须由使用者提供 workspace 外的真实请求与可信 contract，配置本地 Skill 来源、
至少两份参考、保留项、写入范围、选择与反馈要求，以及支持的独立验证器。
当前验证器为 `json-export` 和 `exact-text`。公共来源获取、任意 Python 方法沙箱、
必须修改 Skill 的独立行为验收尚未接通时拒绝执行。DSH 单轮 CLI 暂不恢复交互等待状态。
缺少这些能力的任务不能据内置题通过而放行。

## 验证与失败记录

本次最终冻结版本的实测结果见[脱敏验证摘要](../evidence/host-preview-20261025/summary.json)：
62 项核心/适配回归与 2 项真实 DSH Loader/调度器检查通过。
Codex 实际交付 CLI 完成 20 次工具调用；DSH 完成 20 个模型步骤、25 次工具调用。
两边都实际拒绝提前写入，确认正文回执、保护原始输入，通过独立当前产物验证，
自动输出七阶段卡，模型填写 checkpoint 的次数均为 0。
运行记录中的源哈希前后一致；DSH 锁文件审计所有级别告警为 0。
这些是受控用例数据，不是跨任务正确率或通用性能对照。

以下开发命令在 GitHub 源码仓库根目录运行；安装 ZIP 只包含运行资源，同学使用 CMD 入口。
`npm run test:hosts` 测核心和两种适配器；`npm run test:host-native` 使用明确提供的
DSH runtime 运行真实 Loader/调度器；`npm run test:host-preview` 核完整包、篡改、缺文件、
安装副本、备份及报告脱敏。Windows 原生解压与安装另有显式开启的实际测试。
这些测试不自动调用付费模型。

维护者保留最终版本的真实模型输入、工具返回、当前产物、独立验证、拒绝和代码哈希，
同时保留先前失败：同轮读取审核漏洞、错误来源句柄造成反复读取和预算耗尽、
字段名 `sum` 与要求的 `total` 混淆，以及 Windows 自带 PowerShell 的模块环境差异。
失败不计通过；代码变化后的旧测试不为新版本背书。

用户提供的 197 个 Skill 与 12 个 fixture 的 A/B 反馈是外部报告；未获得原语料和评分器，
本仓库没有将其统计计为本地复现结果。它提出的“先侦察、证伪依赖、冻结答案、全量校验”
用于指导验收，宿主自动记录应降低填表负担，而不是替这些实质步骤盖章。

CLI 与原生接口细节见 [Codex](../hosts/codex/README.md)、[DSH](../hosts/dsh/README.md)。
