# DSH 试用诊断与恢复

不要发送 `.credentials.yaml`、API Key、登录令牌、完整私人会话或账号目录。
诊断仅需版本、选中的目标路径（可遮去用户名）、错误文字及本次测试的工具记录。

| 现象 | 检查与恢复 |
| --- | --- |
| 双击窗口立即退出 | 确认“全部解压”，`windows/Manage-DshSkills.ps1` 与 CMD 相对位置未变；在解压目录的终端运行同一 CMD 读取错误。 |
| 被系统/学校策略阻止 | 核对下载来源；设备策略不可自行绕过。用手动复制，或请设备管理员处理。不要全局 Set-ExecutionPolicy。 |
| `Foreign/unmanaged skill` 或同名冲突 | 已有文件未被改动；检查来源并备份。不要删除收据冒充新安装，不要合并目录。需要保留原版时选另一个测试 Windows 用户。 |
| `Changed or missing file` / `Extra ...` | 文件被改过、缺失或多出笔记/空目录；先完整备份到别处。手动比较变更，恢复原安装文件后再检查；保留定制时不要更新/卸载。 |
| 清单/版本错误 | 重新下载同一固定版本并完整解压；不要手改哈希来让检查通过。 |
| `Not installed` | 确认目标 home；只安装一份时给 Check/Update 加相同 `-Skill` 参数。 |
| `Reparse point/junction` / `Linked payload` | 安装器拒绝符号链接、junction 和联接父目录；选择普通用户目录。不要让脚本删除链接目标。其他 Skill 是链接时也会保守拒绝安装。 |
| `.agent-workflow-skills.lock` 已存在 | 先确认没有另一个安装/更新/卸载窗口或进程。正常失败会自行释放锁；强制结束可能留锁。把该锁移到别处留档后重试；绝不在操作仍运行时移走锁。 |
| 提示保留 `.agent-workflow-skills-stage-*` | 操作或回滚受阻。停止重试，先把这个目录及相应安装目录复制到外部备份。`*-old` 是原目录，`*-new` / `*-failed-new` 是新稿；不要直接删。确认进程已退出，核对有效收据与文件哈希后，由维护者恢复到对应技能名路径。其他 Skill 和配置无需动。 |
| `Changes are committed; backup cleanup failed` | 新版本已提交并保留，或卸载已从技能目录移走，但备份清理未完成；退出码仍为失败，不能报告完整成功。先运行 Check 核当前安装，备份残留目录交维护者处理。残留 old 可能已部分删除，绝不能拿来覆盖健康新版本。 |
| Check 通过，但 DSH 找不到 | Check 仅测文件。确认是官方 Desktop、目标与实际 home 一致，开新对话；保留当前目录证据。Provider 只扫描根下一层，避免 `skills/repo/skills/name/SKILL.md`。 |
| 显示的是旧版本 | 可能有更高优先级的项目 `.dsh/skills`、项目 `.agents/skills` 或自定义目录；请 DSH 报告实际加载基目录，先查冲突，不删除无关文件。 |
| `/技能名` 没加载 | 必须在直接用户消息第一行开头，拼写完全一致；保留注入内容/工具记录。不要只凭模型说“已使用”判成功。官方版本或运行配置不同仍可能不兼容。 |
| references 读不到 | 按技能加载结果的基目录读取。不可只复制 SKILL.md；Check 报缺失时重新完整解压/安装。 |
| 普通问答正常，任务工具报错 | 这是任务能力/权限问题，不能记成 Skill 安装失败，也不能记成任务成功。记录哪个工具缺失及原始错误，不要求同学安装开发工具补测。 |
| 后半程漏规则/出现 middle pruned | 长工具结果可能在压缩时裁剪。从安装目录分段重读完整说明及当前阶段引用；记录范围。必要时新对话显式调用并带当前产物，保留压缩失败记录。 |
| 卸载后名字仍在 | 新对话中检查实际来源；项目、共享目录或其他 Provider 可能还有另一份。不要扩大卸载范围。 |

## 获取最小诊断

在解压目录运行或双击 `Check-DSH.cmd`；仅检查当前选中项目安装的文件、版本和收据。
需要自定义目录时：

```powershell
.\Check-DSH.cmd -DshHome "D:\My DSH Data" -Skill proactive-skill-discovery
```

把可见输出复制到[反馈表](trial-kit/feedback-template.md)。脚本无遥测，不自动上传日志，
也不会检查整个用户目录。故障导致回滚残留时保留现场，不要把“脚本已退出”写成“已恢复”。

## 测试环境恢复

安装器正常卸载后，删除自行创建的任务输出即可。A/B 测试推荐使用独立 Windows 测试账号；
测试结束可以退出该账号。不要清空原来的 `.dsh` 或 `.agents`，不要复制个人配置到反馈包。
异常断电/杀进程、磁盘耗尽、杀毒软件锁定和企业策略未在本地测试，发生时作为失败记录提交。
