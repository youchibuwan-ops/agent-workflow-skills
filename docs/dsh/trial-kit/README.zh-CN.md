## 测试前隔离

优先新建一个 Windows 本地测试账号，在该账号中安装官方 Desktop 并正常登录。
这样不会读取你原来账号的 `.dsh`、`.agents`、插件或 QQ Bridge。不要复制个人配置。
普通同学若不方便新建账号，可以只试安装/显式调用，但**不能声称完成干净 A/B 对照**。

创建一个空的 `DSH试用` 文件夹，里面放 A、B 两个任务副本。不要把任务建在本仓库里面，
仓库中的项目规则、既有结果或已安装技能会污染测试。两个副本内容必须相同，
都没有 `.dsh/skills`、`.agents/skills` 或额外 AGENTS.md。确认实际工作目录就是该副本。

固定相同 Desktop 版本、模型、推理设置、工具权限、网络状态和时间上限。
记录开始/结束时间及遇到的弹窗；不要为 B 额外开放 A 没有的工具。保留真实失败。

## 第一轮：无 Skill / 有 Skill，完全相同提示词

1. **A 无 Skill：** 尚未安装这两份 Skill 时，新对话核查它们不在目录；选 A 任务副本，
   发送下面的“自动触发 / A-B”提示词。保存原始回复、实际工具记录及产物。
2. 双击 Install 安装，Check 文件后，在新对话核对这两个名字出现。
3. **B 有 Skill：** 选未被改动的 B 副本，使用完全相同提示词，不能添加 `/技能名` 或暗示规则。
   检查实际 `skill` 工具调用，再检查全文、引用读取和任务结果。模型仅说“使用了”不算。
4. 每份 Skill 的任务分别做 A/B。未被测的那一份可以同时存在，但记录是否意外调用。
5. 为减少先后顺序影响，后续可用新副本做 B→卸载→新对话→A。若两份原始目录还有其他
   来源的同名项，先报告污染，不能标“无 Skill”。不要删除无关来源来凑结果。

建议至少每组做3次独立新对话。样本少、网络不稳或工具受限时如实记录，不计算虚假的提升率。
同学先不要读本仓库旧案例答案；由核对者在运行结束后对照评分。

## 任务一：发现与适配工作流

将本目录 `discovery-project` 内的 `orders.csv`、`rules.txt` 复制到 A/B 各自任务文件夹。
这是离线可完成的小任务，首次运行不允许安装新工具，故不能覆盖完整的外部 Skill 检索/安装能力。

自动触发 / A-B 相同提示词：

```text
我不熟悉 CSV 数据核对，之前导出的统计反复不一致。请检查这个文件夹里的
orders.csv 和 rules.txt，定位具体偏差，先核可用能力，必要时查现成方法，
再生成正确的 summary.csv 和可复算的核对记录。实际验证输出。
不要改输入，不要安装软件、修改个人技能或发布。工具不足时如实记录受阻。
```

单独的显式调用测试（不计入同提示词 A/B）：在新副本、新对话发送
`/proactive-skill-discovery`，下一行附上上面的原始提示词，并要求实际读取
`references/adapting-upstream-skills.md` 和 `references/learning-from-work.md`。
核对具体能力诊断、规则适配和真实输出；不以引用了标题代替读取证据。

本任务验证有限：不测试联网发现、外部 Skill 安装或个人 Skill 维护写入，不能报告完整总流程已通过。

## 任务二：SVG 整件与局部

只把仓库 `examples/controlled-bracket/reference.svg`、`faulty.svg` 复制进 A/B 副本，
不要给模型 `source.svg`、comparison.png、旧 README 或下面的核对答案。
这是自有精确矢量参考，不是照片复原，不测试多角度实物研究。先确认 Desktop 能渲染并看图。

自动触发 / A-B 相同提示词：

```text
请对照 reference.svg 精修 faulty.svg 这个实体折板的可编辑素材，目标宽160px。
核对完整轮廓、重复孔、折线接合、厚度和遮挡。先把有问题的局部分别做好并实际看图，
再回装整件，检查原尺寸浅深背景并记录观察。输出修订源和检查图。
保留正确部分，不覆盖输入，不接入任何项目，不发布；工具不足时说明未完成项。
```

显式调用测试：在另一个新副本、新对话第一行发 `/crafting-reference-based-svg-assets`，
下一行附原始提示词，要求实际读取 `references/execution-record.md`，按需要读取
`visual-diagnosis.md` 和 `project-profile-example.md`。只有实际渲染/打开当前图、
独立局部修订、回装与新整件检查齐全，才可记本任务对应范围通过。

## 相邻反例：不应触发

新对话逐个测试，不要放在复杂任务的同一上下文中：

```text
2 加 2 等于多少？只回答数字。
```

```text
只把 title.txt 中的 hello 改为 Hello，不改其他内容。
```

```text
请把 icon.svg 的填充色 #000000 改为 #336699，保持几何不变。
这是抽象图标，不需要实物参考。只做这一步，不安装新工具。
```

后两项输入直接复制本目录 `negative-project` 的 `title.txt` 和 `icon.svg`。
原文件在每次运行前恢复。检查是否实际调用了不适用 Skill，或擅自扩展搜索、研究、安装。
合理拒绝或未调用要以工具轨迹为依据；目录中列出名字不算调用。

## 安装生命周期和恢复

用同一个干净账号：首次安装 → 再装同版 → Check → 更新同版 → 卸载 → 重复卸载。
每次开新对话查目录。真正跨版本更新要有两个不同测试包；未提供第二版时填“未验证”，
不能把“同版无操作”当成跨版本更新成功。本地跨版本测试使用了明确标记的测试 fixture。
preview.2 另做了真实旧 preview.1 ZIP 到新包的隔离开发者更新测试；这仍不能替代同学自己的更新测试。

在卸载前，可以在已装目录增加一份无关笔记，验证安全拒绝；先备份，再把笔记移到目录外，
不要修改真实工作文件进行破坏性测试。误删、杀毒拦截、错误 home 依[恢复指南](../troubleshooting.zh-CN.md)记录。
不要在普通同学电脑上模拟断电、改 ACL、弄坏收据或创建 junction。
