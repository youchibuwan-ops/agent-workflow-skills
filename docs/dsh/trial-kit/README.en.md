[中文完整步骤和原始提示词](README.zh-CN.md) · [Install](../install.en.md) · [Blank record](feedback-template.md)

No classmate testing has occurred. This kit is a protocol, not evidence of a pass.

Use a separate Windows test account with official Desktop. Do not import personal
DSH settings, skills, credentials or QQ Bridge. Create task folders outside this
repository with no project skill directories or inherited project rules. Without an
isolated account and a verified absent catalog, label A/B environment isolation unverified.

Keep Desktop/model versions, reasoning settings, tools, network conditions and time
limits identical. Copy identical inputs into separate fresh A and B folders; use a
new conversation for each run. Record actual tool traces and outputs, including failures.

Run A before installing these skills. Confirm their absence from the catalog. Install
and Check, start a new chat, confirm presence, then run B using the **exact same** automatic
prompt in the Chinese protocol, with no skill name or slash token added. Each task has
an explicit `/name` variant in a separate chat; it is not an identical-prompt A/B run.
For repeated trials use fresh inputs and, if possible, reverse the order after safe
uninstall. At least three runs per condition are useful, but a small sample proves no
general improvement claim.

Discovery task inputs: `discovery-project/orders.csv` and `rules.txt`. The task is an
offline CSV audit. It exercises diagnosis, method adaptation and verified output, not
network discovery, external skill installation or personal-skill maintenance writes.
SVG inputs: only `examples/controlled-bracket/reference.svg` and `faulty.svg`; keep
the old README, repaired source and comparison sheet hidden until scoring. This exact
owned vector case does not establish photo research or reconstruction ability.

Test unrelated arithmetic, one-word capitalization, and a pure abstract-icon color
change as fresh negative cases. Look for actual inappropriate `skill` calls and scope
expansion, not just mentions of skills in the catalog. Verify produced files and real
renders/viewing, never the model's self-reported pass.

Exercise install, identical reinstall, Check, same-version Update, uninstall and repeat
uninstall. A real cross-version update needs two distinct packages; if only one exists,
record unverified. Local developer update evidence uses a labeled synthetic next-version
fixture and cannot replace that student test. Do not simulate crashes or corrupt receipts
on the classmate's computer.

Record each layer independently in the feedback form. Share only redacted trial inputs,
outputs and relevant trace excerpts with the maintainer. No credentials or private session
history. The package uploads nothing. For errors preserve the visible message and follow
the recovery guide; do not reinstall official DSH or change unrelated configuration.
