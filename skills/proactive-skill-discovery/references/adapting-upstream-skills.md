# 现成 Skill 不完全满足需求时

优先保留上游原版及其来源/许可，用可维护的适配层解决差异。当前用户和项目要求优先于上游默认建议。

## 先诊断，再匹配实际能力

把偏差写成具体事实：当前哪项输出与哪个要求不符、来自哪个版本、哪些检查已执行又没有覆盖它。优先做能区分原因的小检查，而非重复同一次自评。

| 当前证据 | 下一动作 |
| --- | --- |
| 关键输入或结构依据缺失 | 定位最小缺口，查一手资料或提出必要澄清；工具名称不能补出事实 |
| 方法明确但运行时、权限或配置不符 | 核实际环境与版本，修调用或用兼容替代；不把环境失败记成方法无效 |
| 当前方法不提供所需机制 | 按机制查 Skill/现成工具，并核源码中是否真的实现 |
| 流程已有对应步骤但没有执行 | 回该步骤完成动作及验证；不靠安装第二份相同 Skill 转移问题 |
| 检查范围小于交付范围 | 补实际范围、邻接/保留项与失败路径检查；原通过只保留其有限含义 |

缺口契约可简记为：**输入与已知约束 → 必需机制 → 输出 → 检验方法；可用宿主/依赖与禁止动作**。例如“根据已知三维点和照片点拟合透视相机”不同于“从照片自动恢复任意三维结构”；同含建模关键词也不能互相替代。

候选按契约比较，而非按标题、星数或安装量放行。实际定位到能完成关键动作的段落/脚本及调用条件，同时核必需输入是否拿得到、输出能否接回原任务、依赖是否可用、许可/副作用是否合适。明确区分直接覆盖、需薄适配和不支持；只有通用鼓励或缺少核心算法时，不声称已有该能力。

先试可验证的小范围，把采用的方法和实际结果对应起来。失败回到上述原因分流；换工具仍需重新核相同交付条件。一个候选已足够就停止扩展清单，普通复用不重复全网检索。记录重要拒绝理由和已核版本即可，不为数量安装，也不强制新建日志系统、服务或后台任务。

| 需求差异 | 处理方式 | 需要验证 |
|---|---|---|
| 输出格式、检查深度、工具选择或个人偏好不同 | 薄适配 Skill/项目配置，明确替换哪些默认行为 | 任务结果符合本地要求，同时保留原能力 |
| 要组合搜索、审查、安装、使用等多个步骤 | 一个总控 Skill，规定输入输出与交接边界，按需调用现成能力 | 不跳步骤、不重复审批、不扩大权限 |
| 缺少重复且确定性的计算、渲染、转换或API操作 | 在 scripts/ 增加小工具，说明输入、输出、依赖和副作用 | 真实成功/失败用例；不是只检查脚本存在 |
| 核心算法/流程需大改，适配层已难理解 | 在许可允许时建立有来源记录的分叉 | 固定上游版本，记录差异，更新时比较并重测 |
| 实际不适用于该任务，或者缺少所需能力 | 拒绝此候选，换技能或直接完成任务 | 不用安装量/名称掩盖能力缺口 |

## 来源与许可关卡

适用于本次新采用或实质变更的外部 Skill、工作流、库和素材；已有同版本、同用法且可追溯的审阅可复用。无需为每次常规操作重审操作系统和全部传递依赖。仍须核新版本、改变用法或新增分发责任。

按下列顺序完成，不能用“已下载”“MIT”“看起来适用”填空代替动作：

1. **绑定实际项。** 确认作者/官方来源、路径和版本/提交；核下载或已安装内容与该版本对应。索引只是入口。针对当前缺口，实际读一手方法文档、所需资源/源码段或 Skill 正文，说明它提供什么机制、还缺什么条件。
2. **读许可正文。** 从同版本包内或上游一手来源取得适用的 LICENSE/COPYING/NOTICE 等并实际打开阅读。`curl -o LICENSE`、HTTP 200、文件哈希、SPDX 标签或记忆中的许可常识都只证明有限事实。被截断的输出不能声称已读未展示的部分；继续读取必要条款。没有许可证、正文无法取得或范围冲突时，不声称获准；继续查一手依据或换已核方案。
3. **判断当前用法。** 区分执行已安装工具、改写/复制代码、嵌入字体/素材、再分发 Skill/产物；写清适用范围、需保留的正文/署名/通知，以及限制或待核项。仓库 MIT 不自动覆盖其中的字体、图片或子目录专用条款；不能把“公开可读”当作复制/分发许可，也不把许可名称机械地等同于拒用。
4. **留下可核证据，再执行。** 沿用任务已有记录，用最短条目记录下列信息；没有固定新建文件要求。以真实工具返回或本地读取对应的路径/章节、版本和可选事件号/哈希支撑，不伪造“已看过”的自述。只抄标题、保存空模板或勾选复选框不放行。

| 实际采用项与当前用法 | 来源/版本及已读方法位置 | 已读许可正文位置与适用判断 | 采用/拒绝及应核产物 |
| --- | --- | --- | --- |
| 具体项；执行、复制或嵌入等 | 一手地址/本地路径；章节/源码段；读取证据 | 正文文件/适用条款；义务、限制与未决项 | 为什么覆盖缺口；输出与验证方法 |

安装前可先用可信渠道检查发布包的元数据与内容；需要下载才能读包内文件时，获取和审阅不等于允许执行其中未知脚本。遵守当前任务的联网/写入和安装授权。下载的审阅副本与实际执行版本不符时重新核对。

**换方案就重开对应关卡。** 审过并拒绝 A，转用 B 或加了字体 C，必须分别核 B/C 的方法、来源和适用许可；不能引用 A 的记录为 B/C 放行。安装成功和最终产物正确也不能补造缺失的审阅动作。最终交付前核对“实际使用清单”与审阅证据；漏项继续补做并如实记录审阅发生时间，不能倒填成执行前已完成。

## 适配层契约

写清任务触发、所依赖的现成能力、保留的行为、替换的默认行为、额外约束、验证办法与停止点。依赖未安装或工具不可用时要有可行替代，不假装已调用。不要让一个 Skill 因过宽描述接管所有无关任务。

例如：现成 find-skills 提供关键词发现和安装建议；用户已委托自主搜索、筛选、必要的个人目录安装和调用时，总控 Skill 在遇到能力缺口后自行调用搜索，实际审阅内容和许可证，选择单项并安装/使用。保留其发现能力，替换每次展示长列表并再次询问是否安装的默认交互；任务是否成功仍由真实产物验证。

## 代码为何可选

SKILL.md 定义何时做、怎样做及成功标准；scripts/ 实现需要重复、可靠执行的动作；references/ 放细节与规范；assets/ 放模板。代码多不代表技能更完整。现有工具已能可靠完成时只写流程；确实缺少工具时才加代码及相应测试。

## 分发和更新

保留上游许可证和必要署名，不将公开可读误当再分发许可。私有项目规则、机器绝对路径、任务当前进度与真实凭据留在项目，不进入通用版本。打包后在没有原项目背景的情景中测试，确保既能做目标任务，也能识别不适用的相邻任务。

以单个目录分发时，从空目录实际安装该单项，再读取其引用资源，并核对上游许可要求的正文/署名是否随包保留；仓库根部存在许可证不证明单项安装带上了它。对比已核查源与安装后的文件内容；安装器退出成功只证明安装步骤结束，不证明资源完整或任务能力有效。
