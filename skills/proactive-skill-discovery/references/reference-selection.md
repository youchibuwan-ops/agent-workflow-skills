# 主动寻找、比较并应用相关材料

在新任务启动时使用。目标是由执行者自己学会定位相关元素、专业方法与成熟案例，而不是等用户指出做法。用户反馈可以修正方向，不是开始研究的前提。

## 从需求找到相关对象

先拆出输入条件、目标输出、关键作用机制、完整过程、受影响对象、保留规则和验收方式，再形成检索词。把“做得专业/好看/可靠”变成可查的结构、过程或机制；只搜物件名称容易找到外观相似但用途不同的东西。

同时查专业 Skill 和任务材料。Skill 提供怎么做、怎么验证的方法；官方文档、原始数据、成熟产品/作品和实际案例提供事实与效果依据。二者不能相互冒充。按来源权威性、内容质量与本次机制匹配筛选，不按知名度或安装量定结论。

## 多个相关实例，形成可比较的候选

- 主动寻找多份独立来源及多个成熟实例，核完整需求；不是用户说出一个例子就只围着它搜。
- 存在用户需要决定的主要方向时，整理通常3—5个互有区分、可实际查看的候选。每个候选给出：实际材料/可用链接、来源和已查看范围、解决的具体需求、关键差别、如何适配本任务、限制或不匹配项。
- 将候选呈现在同一比较尺度上，推荐一个并说明依据，让用户在初稿制作前先选主要方向，再按选定方案制作初稿并根据反馈调整。不能只报名字、丢链接、等待用户代做研究；不能先做作者推荐的完整初稿再补选，也不能倒称用户已选。仅在用户已经明确选定或明确要求自主取舍时按该指令执行，不重复询问。
- 用户已明确选择或委托自主取舍时按其要求执行；只提交有实质区别、尚待反馈的主要选择，不把已定细节反复变成评选。明确限制的任务不扩成无关方案评选。候选不足或关键资料不可判断时补查；相关机制、同义词及其他可靠来源均无新增依据时报告缺口与替代路径，继续可独立完成的部分，不无限重复搜索、不凑不相关实例、不虚构看过。
- 用户提出“像某个例子”时，把它转成待验证的机制线索，与其他相关实例一起比较。明确指定“就按此方案，不再选”才视为已经锁定方向。

## 判断资料是否足以支持本次决定

实际打开原始材料。视图清晰度、角度、版本、时序、输入条件与上下文须足以判断要借鉴的具体要素。缩略图、单帧或摘要只支持它实际展示的内容；高清标签也不证明源内容清楚。动态、性能、可靠性或因果判断要有相应过程/实验依据，不能从一个漂亮截图推断。

把可观察事实、解释和适配设计分开。借鉴机制后仍需验证与当前玩法、数据、环境、审美或业务约束一致；参考不是照抄素材或改掉需求的授权。

例如：制作游戏低频波，应在开画前主动找多个游戏的同类声波/压力波，实际核发射、传播、目标命中/受击与消退，比较它们的节奏、形态和反馈如何对应本游戏；先给用户清楚的动态参考和方案对照，用户选定后做出包含完整攻击与受击过程的可看初稿，再按反馈调整。不能只画传播主体，等用户指出命中对象后才补找资料。软件方案则比较对应机制的成熟实现、官方约束与实测条件；分析任务则比较可信数据源、方法与适用假设，而不是把游戏案例硬套到其他领域。

## 将反馈转成下一次能主动执行的经验

用户明确提出的通用工作方式是已确认要求，应写入通用流程的触发、行动、产物和验收；具体偏好与项目事实留在项目。经验应是“新任务主动找对应机制的多个实例并交付比较”，不是“以后都用某款游戏”或“等用户再次提供例子”。方法是否有效仍要用新任务和相邻反例验证。
