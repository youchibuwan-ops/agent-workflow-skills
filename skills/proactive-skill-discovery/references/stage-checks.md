# 阶段检查与宿主阻断

## 输出与证据分开

模型必须在对应动作之间输出任务卡、能力核验单和阶段检查记录，最终输出交付核验单。只输出一份 JSON、填满字段或在结束时补写记录，不证明已经按顺序执行。

首次输出按“任务卡 → 强制执行状态 → scope 检查”排序，完成后才检索/核读候选。
尚未加载正文时只允许引导读取本 Skill 和流程规则，不能顺手查询 catalog、读专业候选
或参考。`research` 工具在 scope 阶段由门禁拒绝；如需引导读取，宿主应另给参数受限的
`scope` 工具，只能读自身规则和边界输入，不能把通用文件读取器无条件映射为 scope。

阶段检查记录包含 `task`、`revision`、`stage`、`done`、`evidence`、`missing`、`next_action`。`done` 是可核实动作摘要，不要求公开内部思考过程。`evidence` 指向本次实际工具返回、文件及版本；隐私原始记录保留本地，不上传凭据或整段私人会话。

| 阶段 | 进入下一阶段前必须成立 | 缺项后的动作 |
| --- | --- | --- |
| scope | 当前用户授权、完整目标、保留/禁止项、停止点 | 回答边界问题；不擅自恢复任务 |
| discovery | 实际查找；当前完整正文、相关引用/脚本、适用许可证；多个相关参考；适配决定；必要安装/复用及读回 | 留在核验；补最早缺项，继续独立研究 |
| selection | 给出实际可比方案，取得用户选择；或引用用户已选/明确自主授权 | 等选择，不替用户选择后制作 |
| draft | 实际用上核验过的方法；当前完整初稿；每份产物分别自检 | 修订当前初稿，重新检查 |
| feedback | 对当前初稿的真实反馈已处理；明确委托技术自主验证时记录原指令和边界 | 等必要反馈或返工；不虚构审美认可 |
| delivery | 每个原始要求/反馈均对应当前产物及实际验证 | 回到最早失败阶段 |
| learning | 已验证的可复用增量实际维护并做行为复验；无增量有具体核查理由 | 完成维护；未验证不得称完成 |

参考少、没有合适新 Skill、网络禁止、工具不可用、只读任务等分支保留事实及授权边界。用户限制联网时不得硬做外搜。某候选确实不适用可以拒绝，不为数量安装；缺少覆盖本次关键需求的方法时，不因此伪造采用和安装成功。宿主可接入已验证的既有技能作为 `reuse`，仍核本轮版本、覆盖和完整文件。

## 可运行检查器

包内 [workflow-gate.mjs](../scripts/workflow-gate.mjs) 是 Node.js 22+、无额外依赖的阶段状态机。它供**可信宿主/协调器**导入，不是让模型自己给自己盖章。普通对话加载此 Skill 不会自动修改 Codex 或 DSH 配置。

```js
import { randomBytes } from 'node:crypto';
import { WorkflowGate, sealEvidence } from '../scripts/workflow-gate.mjs';

const privateKey = randomBytes(32); // 仅宿主持有；不要暴露给模型/工具可读目录。
const gate = new WorkflowGate({ task: 'task-001', revision: 1,
  key: privateKey, root: '/absolute/authorized/workspace' });
// collector 必须观察真实工具执行/返回、当前文件和原始用户指令后才签发回执。
// report 来自模型；receipts 来自可信 collector，不能直接签模型提交的事实。
const result = gate.advance(report, receipts);
if (!result.ok) console.error(result.errors);
```

上例展示调用边界，`report`/`receipts` 由宿主提供，不是可独立运行的完整主程序。可从仓库的 `scripts/workflow-gate.test.mjs` 查看完整、可运行的受控实例。

回执含 `id/seq/task/revision/kind/data/signature`。HMAC 仅证明来自持钥宿主，不能证明宿主观察正确；可信 collector 必须独立核对原始返回，不接受模型自填 `read=true`。当前文件快照含相对 `path`、`sha256`、原始 `bytes`、实际 `returned_bytes`、`truncated:false`。源与安装副本使用 `relative_path` 对齐完整 manifest；相关脚本、引用和许可证均列入 `required_files`。完整文件已返回、是否确实覆盖专业问题及视觉质量是不同检查。

检查器拒绝：乱序推进、scope 未过就开始候选研究、其他任务/修订回执、重复/倒签回执、自签伪造回执、缺必填输出、缺核读/安装、截断、文件改变/越界、安装与已审 payload 不同、模型替用户选择、未验证产物混入交付、未通过或旧版行为测试冒充维护、用户暂停及越过停止点。scope 回执还需冻结全部需求 ID，交付不能遗漏或替换其中任一项。`reopen(stage, reason)` 重开相应阶段并递增修订；暂停不能由它恢复。

`gate.run(stage, callback)` 在检查通过后才执行该阶段的受控动作。`gate.guard(toolStages)` 返回默认拒绝未知工具的同步 guard，供宿主接入。`toolStages` 由宿主管理：确实只读且参数受限的工具可标 `research`，写入/制作工具映射到对应阶段。**不能把通用 shell、浏览器任意脚本、文件写入或可转发任意调用的工具标成 research。** 必须纳管子调用及所有写入路径；没有接入的工具不受这个模块限制。

## 两种使用状态

### instruction_only

只安装 Skill 时默认属于此状态。仍必须执行固定输出、前置核验及停止规则；但不能声称工具层已经强制阻断。模型遗漏这些记录同样判行为失败，不能用安装成功或检查器单元测试替它放行。

### host_guarded

宿主创建 gate 并控制 collector、密钥、状态及工具白名单。严格模式启动前实际尝试“未核验直接写入”和“未知工具绕过”，检查错误返回且主体未运行；测试通过后才进入纳管任务。故意缺一项、改旧源、替换安装副本、提交失败测试均须被拒绝。工具包装器不能让模型直接修改状态或密钥。

- DSH 可将 `gate.guard(trustedToolMap)` 注册到原生 `ctx.tools.guard`。正式发布的接口应以本机版本核实；原生 dispatch 和模型实际调用分别测试，不互相替代。
- Codex 的前置 hooks 需实际验证当前会话加载、信任、工具覆盖和拒绝效果；源码存在接口不等于本机会话已接通。已有交互 shell、没有前置 hook 的工具、hook 崩溃/超时等路径必须单独核查。未纳管路径存在时，禁止宣称全局“无法跳步”。

阶段状态机证明的是已纳管操作不能越过已定义前置检查。它不自动判断艺术审美、事实真伪或所有未来任务的正确性。没有接入宿主时，严格无跳步验收仍未通过，不能隐去这一差别。

## 行为回归

维护者在真实、全新模型上下文中执行实际文件任务，保存原始工具返回和当前产物；并用同任务旧版/无指令对照及相邻反例检验。至少覆盖：只搜标题、旧快照、缺许可证/脚本、安装失败、未选先做、已选重复问、状态追问、暂停、来源/产物变化、失败测试与总结未落实。

程序逐项检查文件和时序，人工核实际返回是否足够、候选是否适用、方法是否真被使用。输出正确但跳步仍失败；字段齐全但没做仍失败；两边都正确记平局。保留所有失败和环境阻塞，修订后用新目录复测，不能覆盖旧记录或把自填通过当结果。
