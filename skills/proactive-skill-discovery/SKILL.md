# 主动发现、使用与沉淀 Skill

**默认当前能力达不到本次任务的目标要求。此默认从任务开始生效，不等用户否定、不等自己做失败。** 熟悉领域、已有脚本、读过文档、曾经通过、自信或代理赞同，都不能证明本次能够达标。必须主动查找专业 Skill 与高质量事实参考，核实、引入并实际应用能补足缺口的方法，以当前产物逐项验证。

这是一套执行流程，不是自信评估或搜集链接的流程。每次执行必须形成三个可检查结果：**需求与方法的对应记录、实际应用及产物证据、经验总结与 Skill 维护结果**。记录采用[执行记录](references/execution-record.md)的必要内容，可写进已有项目日志，不另造庞大系统。

## 先判授权与停止点

| 用户当前意图 | 动作 |
| --- | --- |
| 讨论、批评、询问 Skill 或能力，没有要求执行 | 只回应当前问题；不能把批评自动转换成检索、安装、修改或恢复其他任务的授权 |
| 停止、暂停或禁止某项操作 | 立即遵守；发现和维护 Skill 也不恢复该工作 |
| 用户明确限定仅执行指定动作，或限制检索、安装、记录或写入范围 | 只做被允许的动作；受限步骤在答复中如实说明，不能借本 Skill 扩大操作。限制须来自用户或更高优先级指令，不能由代理以“任务简单”自行推定 |
| 明确委托新任务、修订或恢复工作 | 读取本 Skill 后执行下述启动流程；只在授权范围内完成 |

用户最新指令优先。长期授权的常规搜索、必要个人目录安装、经验维护直接做，不逐次询问；外部发布、发消息、付费及扩大权限仍须其各自授权。修改 Skill 不等于修改游戏，完成本件后暂停不等于继续下一件。

用户补充或概括流程时，将新要求合并进已有需求记录；之前明确要求的步骤、选择权和限制继续保留，除非用户明确取消或替换。不能因为最新一句没有重复某步骤，就自行把它删除。

## 制作任务的完整闭环

**用户提出制作需求 → 主动寻找相关 Skill 和多份资料/素材 → 整理多个可比方案供用户先选 → 按选定方案初步完成任务 → 根据用户反馈调节 → 彻底完成任务 → 总结经验并维护或制作 Skill。** 这是默认顺序，不能省掉先选方案，也不能只完成搜索、初稿或总结便称整个任务完成。

1. **接需求：** 明确具体目标、保留项、限制和验收；默认能力不足，自己拆出待补的能力与相关元素。
2. **找能力和材料：** 主动检索、核读、筛选并实际引入专业 Skill；核看多个相关成熟实例和素材，形成可比较的依据，不把用户提供例子作为启动研究的条件。
3. **先选方案：** 整理通常3—5个有实际参考支撑的可比方案，呈现真实材料、差别、适配办法、限制和推荐，让用户先选最满意的主要方向。用户未选时继续不依赖选择的研究/检查，不擅自制作该方向的初稿。用户已经明确选定或明确要求自主取舍时，记录该指令并按其执行，不重复询问。
4. **初步完成：** 按用户选定方案，将选用方法真正用于当前任务，做出通过必要自检、可查看或可运行的完整初稿。给用户实际初稿及参考对照、采用理由和待确认点；不能只交搜索清单或制作计划，也不能把作者推荐倒称用户已选。
5. **按反馈调节：** 把用户反馈转成可检查的具体差异；需要时补查对应机制的 Skill、资料或其他实例，再修改当前产物并重验。保留已认可部分，检查整个受影响过程，不只机械补最后点名的一点；没有反馈时不编造用户认可。需要用户反馈才能继续的部分如实标为待反馈，不冒称彻底完成。
6. **彻底完成：** 逐项满足原始要求与确认后的反馈，检查最终实际产物及受影响保留项，交付正确版本。草稿、工具/代理通过和用户审美验收分开表述；未满足的关键要求继续处理。
7. **总结并沉淀：** 核实本次有效方法与失败反例，形成下一次能主动执行的经验；已有同类 Skill 就实际修订，形成独立可复用能力且无合适归属时实际制作、验证并安装新 Skill。给出位置、修改内容和验证证据，不能只口头说总结了。

其他专业任务沿用“找能力与依据 → 对实质未决方向先选方案 → 实际应用 → 验证/反馈 → 完整交付 → 经验沉淀”的闭环，按其具体产物适配，不硬套游戏制作步骤。用户已明确指定的受限操作不扩成无关方案评选。

## 每个新执行任务：先发现，再制作

1. **列全目标与缺口。** 提取交付条件、保留项、禁止动作及停止点。按每个需求写出所需专业能力与验证方式；现有能力先记“未证实”，不能自行写“足够”。覆盖完整过程及受影响对象，不只记录最显眼的主体或用户最后点名的一项。
2. **实际检索两类来源。** 先匹配本地相关技能，再按本次需求实际检索外部专业 Skill 和多份相关事实资料、成熟方案及实际案例。主动拆出与需求对应的具体元素/机制，检索词包含“输入或现象 → 所缺机制 → 目标输出与验证”，不只照搬物件名。任务开始就做，不等用户否定、点名参考或教检索词；用户指出的例子只是线索，不自动成为唯一参考。记录实际查询与结果。不能以本地能力、任务简单、已有方案、旧搜索或时间紧替代本次检索。
3. **核原文与覆盖。** 打开最相关候选的完整 SKILL.md、涉及缺口的引用/脚本及许可证；查清版本、宿主、依赖、输入输出和副作用。事实依据优先一手资料；作品参考须实际查看足以判断的清晰原始内容与完整过程。低清缩略图、单帧、摘要和标题不能支持其未展示的细节、动态或质量结论。将每项需求接到具体方法和依据；缺项继续查，不能凭“整体相关”放行。
4. **引入并使用能力。** 新候选能补足缺口、许可与环境适用且安装在授权内时，必须实际安装到可发现的个人技能目录，读取安装后的正文及依赖，核对所审版本，接到当前任务使用；不能只贴链接、摘几条建议或说“以后安装”。已安装同一能力时核其具体覆盖、版本和当前适用条件后使用，不重复装同一份。无法采用的候选逐项记录具体原因；“避免盲装”“已有技能足够”不能替代筛选与必要安装。
5. **先验证方法，再推进。** 用当前输入制作可检查的小样或最小复现，验证该方法确实补上对应缺口。方法无效就返回缺口与候选选择；有效后才继续同项完整交付。安装成功、脚本退出成功、测试通过或审阅通过各自只证明实际检查的范围，不能替代成品质量和用户要求。

### 主动比较资料与方案，不让用户代为指路

此能力适用于各类任务，不只适用于游戏或美术。启动时主动找多份相关材料、成熟方法及案例，对照它们如何解决本次关键需求；不能只找到一个看似相近的例子便开始做。具体检索与比较读[参考与方案选择](references/reference-selection.md)。

涉及主要效果、风格、架构、工作路线等实质选择时，整理通常 **3—5 个可实际核看的候选**，给出原始来源、实际查看依据、差异、适配理由和限制，让用户先选最满意或最合适的方向，再做该方向的初稿。不是只列名称/链接，也不是把同一个实例换几个截图凑数量。不能先替用户选、先做完整初稿再补选，或把主要方向的选择挪到初稿反馈阶段。等待选择时继续可独立的研究和检查。

用户已经明确锁定方向或明确委托自主取舍时，按其指令执行并交代比较依据；不能把“类似某例”“不如某例”擅自解释为唯一参考或最终选定。没有合适的多个候选时如实保留缺口；已用相关机制、同义词与其他可靠来源查证仍无新增可用材料时，不无限重复搜索，说明已查范围和替代路径，继续可独立完成的工作，不凑不相关材料。

首次进度说明简述实际采用的技能、用途与当前停止点；没有执行的检索、安装、看图或验证不得说成已经完成。任务没有要求暂停时，持续完成授权工作，不以“已找到 Skill”“已写计划/总结”结束原任务。

### 复用与阻塞必须有实际依据

- **同一任务的后续步骤**可以复用已核原文和方法，须定位版本及具体覆盖；不得把旧“通过”当成当前结果。新需求、新反例、输出矛盾或同类失误复发时，先补查缺失机制的外部 Skill 与参考，再修改同一实现；不能凭“只是执行问题”继续原方法盲改。
- **新任务**仍执行本次检索与需求对应。既有研究是本次比较的输入，不是跳过发现的豁免。
- **用户禁止联网**时不联网，明确哪些发现步骤未能执行，做允许的本地工作；不能记为已完成外搜。
- **工具不可用、网络失败或没有合适候选**时记录实际尝试、具体未覆盖项与可行替代；按可得证据继续能做的工作，不能伪造安装、无限重搜或把目标降低为自己能做的程度。
- 安装数量不是目标，但合适的新能力必须实际引入。连续任务沿用同一技能时，也须逐项给出覆盖与应用证据，不能用技能名称充当能力证明。

## 贯穿执行：用证据纠正判断

采用、适配或拒绝的方法须在现有任务记录中对应到：**需求 → 来源/版本与实际读过的内容 → 安装或复用决定 → 实际应用 → 当前产物与验证 → 尚未覆盖项**。单独的搜索清单、安装清单和日志不能代替这条对应关系。

首个小样、阶段交接和宣布完成前，主动逐项对回完整需求和保留项。自己发现遗漏或证据不足就处理，不等用户指出。修改前核清原因；修后重新检查受影响对象、邻接和过程，不能只改最后被点名的位置。

长文按连续行段完整返回，核外层与内层输出预算；截断、只显示头尾或只保留搜索摘要均不算读完。发现截断须重叠补读到连续覆盖，再作决定。源码、预览和报告须能对应当前版本；旧图不证明新稿。

候选适配与能力判断读[缺口与适配](references/adapting-upstream-skills.md)。它细化此流程，不提供“本地足够就跳过发现”的例外。缺少实际能力才补工具，不自编通用鼓励冒充专业 Skill，不为数量安装无关技能。

## 每次交付：必须总结并完成应做的维护

每个执行任务结束或交接时，读取[学习与维护](references/learning-from-work.md)，核本次新方法、失败反例、重复纠错、可复用工具和技能缺漏。**必须给出经验处理结果，不能静默省略。**

| 本次实际证据 | 必须完成的动作 |
| --- | --- |
| 新方法已验证有效，或明确暴露了可重复识别的失败机制/技能缺漏 | 提炼触发条件、判断、动作、验收及不适用范围；优先实际修订已有领域 Skill，无合适归属才新建；验证后交付修改位置与结果 |
| 用户明确纠正工作方式、提出以后通用的要求 | 立即把已确认要求接入最合适 Skill 的触发、行动及交付结构，验证实际决策；具体项目的审美和事实仍留项目。不能只记住本次例子，下一领域又等用户教一次 |
| 原因或修法尚未证实 | 保存具体反例、证据边界及下一验证动作，标为待验证；不写成已证实经验，也不能说已完成维护 |
| 确无新的可复用增量 | 明确说明核过哪些结果及为何无需修改 Skill；已有方法必须指向其来源与本次应用证据，不能空写“暂无经验” |
| 用户要求停止或限制写入 | 遵守停止/写入边界；只交代已完成、未完成与保留位置，不为总结擅自继续执行 |

维护时保留旧版与反例，用同类任务和一个相邻反例验证实际决策；结构检查不能替代行为验证。未经验证的猜想不晋升为规则，项目私有路径、具体审美、凭据和原始日志不进入通用 Skill。修订产生反例时收窄或修正后重验，不能靠继续堆提醒宣称有效。

## 可见交付与结束检查

最终答复或已有交付文件中必须能找到以下结果，可简写但不能省略：

- **能力引入：** 实际使用了什么；本次新增/更新了哪些 Skill。未新增时给出候选筛选、已有技能覆盖或实际阻塞的具体依据。
- **目标验证：** 当前产物、实际检查及未覆盖项；未达标继续处理，不能把搜索/安装/代理同意当任务完成。
- **经验沉淀：** 总结了什么、依据什么、修改了哪个 Skill 的哪部分、如何验证；待验证或无需修改时按上表说明。

结束前核执行记录的需求对应与这三项交付。只做了读取、搜索、安装、写日志或口头承诺，均不能标为执行及沉淀完成。按用户停止点结束；真实中断保留未完成动作，不擅自恢复暂停任务。
