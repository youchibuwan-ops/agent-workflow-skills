# 主动发现、使用与沉淀 Skill

目标是完成当前任务。主动寻找可复用能力只是手段，不能把检索、安装或加载成功冒充任务完成。此 Skill 是总控流程；现成搜索 Skill、网页/GitHub工具和安装器都可作为执行工具，不是硬依赖。

## 触发与范围

开始实质任务时先匹配已安装技能；本地流程足够就直接使用。新领域、明确能力缺口、专业工作难以把握或同类失误反复出现时，主动搜索外部 Skill，不等用户提醒。普通答复和已有成熟流程不机械地反复联网。任务中出现反复纠错、非显然的有效方法、可复用工具或现有技能缺漏时，也主动评估经验沉淀，不等用户提醒。

**主动发现问题，不等用户指出。** 开始时从当前请求提取可观察的交付条件；首个样例、阶段交接和宣布完成前，将当前产物逐项对回条件及受影响的保留部分。工具报成功只覆盖它实际检查的范围。出现不符、证据冲突、旧预览或无法解释的结果，立即定位并处理；不能等同类错误重复多次才启动诊断，也不能只改最后被点名的位置。

当前任务只需常规操作且能力已足够时直接做。需要诊断/匹配时读[缺口与适配](references/adapting-upstream-skills.md)；需要沉淀/复用经验时读[学习与维护](references/learning-from-work.md)。

**能手写不等于已有合适流程。** 准备自行实现非平凡的标准格式转换、解析、打包或渲染时，先匹配成熟 Skill／库能否直接覆盖关键机制，再决定是否补实现；不以熟悉标准库为由跳过这次匹配与必要检索。用户明确要求手工制作的内容、已有足够且已核的流程、常规精确编辑仍按原范围直接做，不为凑检索改写任务。

读取当前用户/项目约束、任务授权及停止点。发现技能不恢复暂停任务，也不改变禁止生图、禁止批量、只读、不得实装等要求。用户已委托自主搜索、筛选、必要的个人目录安装和调用时，在该范围内直接执行，不逐次询问是否要搜/装。Skill本身不授予额外权限；外部发布、发消息等仍按当前任务的实际授权执行。

## 外部方案的执行前交接

仅在引入/更换外部方案时执行此关卡，普通任务不额外检索。先按**产物生成、验证、预览**三个角色列出本轮实际新用项；验证器、fallback 及为启动方案补的实质运行依赖同样在内。

对每项先完成 **S：来源/版本与实际方法片段 → L：已读许可正文与当前用法判断 → R：可见采用记录**，再调用它生产或检查产物。每次读取返回后，先对照**实际收到的正文**，把该项保持为“未核／待补／可用”；不是命令成功就默认可用。

放行时用已有记录或可见进度留一条：**项@版本与角色；准备使用的关键行为/调用条件；返回正文中支持它的短片段和位置；许可适用判断；状态**。解释该片段怎样支持下一次实际调用，而非只抄方法名。只有导航/标题、搜索摘要、空查找或缺关键片段时记“待补”，下一动作是补读该证据或换已核方案，不能先执行该项。来源、许可或用法任一未核就不写“可用”；结尾不得倒填。记录是对真实返回的核对，不是自述已审的通行证。

若一个命令同时下载、输出许可证并执行新方法，拆成“取得/读取 → 看实际返回并判断 → 执行”三段。输出截断或返回无关章节时先补读；不能因 URL 标题正确、完整 stdout 在日志里存在或最终产物合格，就认为已完成审阅。换方法/新增项重开它的交接；不重复审已核同版本同用法的其他项。

## 完整流程

1. **确认缺口。** 明确任务目标、已有技能、所缺能力、宿主工具/运行时和必须保留的约束。先读本地相关 Skill，不重复寻找同一能力。把偏差定位到具体产物/步骤，再区分资料不足、工具环境、方法缺失和执行漏步；不能把每个异常都当作需要再装 Skill。
2. **检索现成方案。** 按“输入/现象 → 所需机制 → 输出与验证”形成关键词，不只搜物件名或用户原话。可使用 `find-skills`、网页/GitHub搜索或可用索引；索引不等于整个GitHub，必要时补查作者/官方仓库与同义词。找到能覆盖缺口的候选即收敛；无新线索时采用可行替代，或说明具体未解决项并继续独立工作，不无限研究，也不把未解决的关键缺口写成通过。
3. **审阅后才放行。** 读[来源与许可关卡](references/adapting-upstream-skills.md#来源与许可关卡)，再打开候选的 SKILL.md、所需引用/模板或实际方法的一手文档/相关源码；核实版本、机制、输出契约和副作用。实际读取对应许可证正文，判断当前使用/修改/分发方式及须保留的通知。搜索摘要、文件存在、下载成功、包元数据中的许可名称都不能替代正文审阅。将真实读取证据和采用/拒绝理由记入当前任务记录；关键证据缺失时不得放行该方案，继续核查或换用已审方案。星数和安装量只是排序线索。
4. **决定复用方式。** 在直接使用、薄适配、多技能组合或有必要的分叉之间选择。别人 Skill 不完全满足时，读 [适配方法](references/adapting-upstream-skills.md)。缺少实际能力才补脚本，不为显得完整而加代码，不把通用提示包装成新能力。
5. **安装选定项。** 已安装的优先复用；确有增益的新项可在当前授权内装到个人技能目录。优先可信安装器，指定单个路径和已核查版本，保留来源/许可；不整库批装、不覆盖同名版本、不顺带改其他代理或账户配置。工具不可用时换已有渠道，不为纯搜索额外装整套运行时。
6. **读本地并执行。** 确认安装内容与所审版本对应，读取选定流程与必要资源；保留当前用户指令优先级。执行前将**实际选定**的方法/工具/素材逐项对回第3步证据；审过被拒候选不代表审过最终采用项。中途换方案、新增实质依赖或字体等资源时，先补对应审阅再用，不能以已经生成产物为由跳过。指出采用哪一方法、作用于哪个步骤及应产生什么可核结果，然后实际用于当前任务。只执行任务真正需要的部分，避免多个技能互相套娃、重复审批或重复生成同类产物。
7. **验证产物与执行证据。** 先用当前小样核所选方法是否真正解决缺口，再推进后续范围；脚本看真实输出，图审实际看图，代码做相应检查。把“实际输入 → 所用方法 → 当前产物 → 检查依据”对应起来，并复核最终采用项确有来源/许可正文读取及适用判断；产物合格不能抵消漏审。安装成功、字段齐全、代理同意或自信程度都不等于任务通过。失败时按原因退回证据、匹配或实现；同方式重试没有新依据时换方法，不继续盲装技能。有必改继续修正、重验，不能用找到 Skill 或写完总结结束未完成的原任务。
   对曾失败的编码、布局、字体或文件互操作，生成器自读可能共享盲区；可用时补另一实现的读取/渲染并处理实际警告，再核内容与当前实图，不能只用同一引擎的自检报完成。新验证器也先过来源/许可关卡；不可用时明确未验证边界，不伪造兼容结论。
8. **保留可复用记录。** 新采用/重要拒绝或适配时，简记来源仓库/路径/版本、许可、实际读过的内容、选择理由和验证结果。保存在项目指定位置或个人技能记录中；不要把机器路径、临时任务状态、密钥或私人素材塞进可分享的 Skill。后续复用已核查方案，更新前比较上游变化并验证本地适配。

9. **主动总结并维护。** 出现上述经验信号时，读[经验沉淀方法](references/learning-from-work.md)，从实际证据提炼可复用决策；优先修订已有 Skill，确无合适归属才新建。在已授权的个人技能维护范围内直接执行并验证，不只提出建议。单次偶发事件或未经验证的猜想留作任务记录。

## 输出与结束

向用户简述采用了哪个技能、为何合适，以及实际结果；不抛长候选列表等用户替你筛选。没有合适 Skill 时如实说明并继续可完成的原任务，不凭空声称已使用。

按当前停止点结束。对“完成本件后暂停”，不得继续下一件，也不得把发现/维护 Skill 当作恢复原队列的许可。
