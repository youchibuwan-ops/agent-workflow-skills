# 阶段检查与宿主阻断

## 输出与证据分开

模型必须在对应动作之间输出任务卡、能力核验单和阶段检查记录，最终输出交付核验单。只输出一份 JSON、填满字段或在结束时补写记录，不证明已经按顺序执行。

首次输出按“任务卡 → 强制执行状态 → scope 检查”排序，完成后才检索/核读候选。
尚未加载正文时只允许引导读取本 Skill 和流程规则，不能顺手查询 catalog、读专业候选
或参考。`research` 工具在 scope 阶段由门禁拒绝；如需引导读取，宿主应另给参数受限的
`scope` 工具，只能读自身规则和边界输入，不能把通用文件读取器无条件映射为 scope。

阶段检查记录包含 `task`、`revision`、`stage`、`done`、`evidence`、`missing`、`next_action`。`done` 是可核实动作摘要，不要求公开内部思考过程。`evidence` 指向本次实际工具返回、文件及版本；隐私原始记录保留本地，不上传凭据或整段私人会话。

已接通的宿主可从真实动作自动生成上述记录，按顺序调用门禁；无需模型再填写同一份 JSON。
自动生成记录不能代替证据采集。尤其**本地目录存在不证明依赖能加载、进程退出成功不证明结果通过**：
可执行方法须有实际可调用探针，结果须对应预先定义的独立标准答案、边界用例或任务验收器。
检查成本应放在实际风险和能力缺口上，不能把可自动记录的凭证变成重复模型回合。

“工具已返回正文”也不自动证明下一审核调用已经能看到它。一个模型回复可预排多个工具，
原生调度器先执行读取再执行审核仍可能发生在下一次模型请求之前。
受控预览入口为每个实际正文范围返回不可预测、一次性的 `source_receipt`；模型在收到结果后，
用 `workflow_confirm_sources` 批量确认。未确认范围、猜测、重放、旧来源及混合伪造批次均不计核读。
宿主还须核对最终原生工具结果未被摘要、溢出文件或压缩替换；挑战确认只证明正文结果可获得，
不证明理解、审美或事实判断正确。覆盖验证不能因此省略。

| 阶段 | 进入下一阶段前必须成立 | 缺项后的动作 |
| --- | --- | --- |
| scope | 当前用户授权、完整目标、保留/禁止项、停止点 | 回答边界问题；不擅自恢复任务 |
| discovery | 实际查找；当前完整正文、相关引用/脚本、适用许可证；多个相关参考；适配决定；必要安装/复用及读回 | 留在核验；补最早缺项，继续独立研究 |
| selection | 给出实际可比方案，取得用户选择；或引用用户已选/明确自主授权 | 等选择，不替用户选择后制作 |
| draft | 实际用上核验过的方法；当前完整初稿；每份产物分别自检 | 修订当前初稿，重新检查 |
| feedback | 对当前初稿的真实反馈已处理；明确委托技术自主验证时记录原指令和边界 | 等必要反馈或返工；不虚构审美认可 |
| delivery | 每个原始要求/反馈均对应当前产物及实际验证 | 回到最早失败阶段 |
| learning | 已验证的可复用增量实际维护并做行为复验；无增量有具体核查理由 | 完成维护；未验证不得称完成 |

参考少、没有合适新 Skill、网络禁止、工具不可用、只读任务等分支保留事实及授权边界。用户限制联网时不得硬做外搜。某候选确实不适用可以拒绝，不为数量安装；缺少覆盖本次关键需求的方法时，不因此伪造采用和安装成功。宿主可接入已验证的既有技能作为 `reuse`，仍核本轮版本、覆盖和完整文件。

## 可运行检查器

包内 [workflow-gate.mjs](../scripts/workflow-gate.mjs) 是 Node.js 22+、无额外依赖的阶段状态机。它供**可信宿主/协调器**导入，不是让模型自己给自己盖章。普通对话加载此 Skill 不会自动修改 Codex 或 DSH 配置。

```js
import { randomBytes } from 'node:crypto';
import { WorkflowGate, sealEvidence } from '../scripts/workflow-gate.mjs';

const privateKey = randomBytes(32); // 仅宿主持有；不要暴露给模型/工具可读目录。
const gate = new WorkflowGate({ task: 'task-001', revision: 1,
  key: privateKey, root: '/absolute/authorized/workspace' });
// collector 必须观察真实工具执行/返回、当前文件和原始用户指令后才签发回执。
// report 来自模型；receipts 来自可信 collector，不能直接签模型提交的事实。
const result = gate.advance(report, receipts);
if (!result.ok) console.error(result.errors);
```

上例展示调用边界，`report`/`receipts` 由宿主提供，不是可独立运行的完整主程序。可从仓库的 `scripts/workflow-gate.test.mjs` 查看完整、可运行的受控实例。

回执含 `id/seq/task/revision/kind/data/signature`。HMAC 仅证明来自持钥宿主，不能证明宿主观察正确；可信 collector 必须独立核对原始返回，不接受模型自填 `read=true`。当前文件快照含相对 `path`、`sha256`、原始 `bytes`、实际 `returned_bytes`、`truncated:false`。源与安装副本使用 `relative_path` 对齐完整 manifest；相关脚本、引用和许可证均列入 `required_files`。完整文件已返回、是否确实覆盖专业问题及视觉质量是不同检查。

检查器拒绝：乱序推进、scope 未过就开始候选研究、其他任务/修订回执、重复/倒签回执、自签伪造回执、缺必填输出、缺核读/安装、截断、文件改变/越界、安装与已审 payload 不同、模型替用户选择、未验证产物混入交付、未通过或旧版行为测试冒充维护、用户暂停及越过停止点。scope 回执还需冻结全部需求 ID，交付不能遗漏或替换其中任一项。`reopen(stage, reason)` 重开相应阶段并递增修订；暂停不能由它恢复。

`gate.run(stage, callback)` 在检查通过后才执行该阶段的受控动作。`gate.guard(toolStages)` 返回默认拒绝未知工具的同步 guard，供宿主接入。`toolStages` 由宿主管理：确实只读且参数受限的工具可标 `research`，写入/制作工具映射到对应阶段。**不能把通用 shell、浏览器任意脚本、文件写入或可转发任意调用的工具标成 research。** 必须纳管子调用及所有写入路径；没有接入的工具不受这个模块限制。

## 两种使用状态

### instruction_only

只安装 Skill 时默认属于此状态。仍必须执行固定输出、前置核验及停止规则；但不能声称工具层已经强制阻断。模型遗漏这些记录同样判行为失败，不能用安装成功或检查器单元测试替它放行。

### host_guarded

宿主创建 gate 并控制 collector、密钥、状态及工具白名单。严格模式启动前实际尝试“未核验直接写入”和“未知工具绕过”，检查错误返回且主体未运行；测试通过后才进入纳管任务。故意缺一项、改旧源、替换安装副本、提交失败测试均须被拒绝。工具包装器不能让模型直接修改状态或密钥。

- DSH 可将 `gate.guard(trustedToolMap)` 注册到原生 `ctx.tools.guard`。正式发布的接口应以本机版本核实；原生 dispatch 和模型实际调用分别测试，不互相替代。
- Codex 的前置 hooks 需实际验证当前会话加载、信任、工具覆盖和拒绝效果；源码存在接口不等于本机会话已接通。已有交互 shell、没有前置 hook 的工具、hook 崩溃/超时等路径必须单独核查。未纳管路径存在时，禁止宣称全局“无法跳步”。

仓库另含 `hosts/core`、`hosts/codex` 和 `hosts/dsh` 的受控测试入口：Codex 使用精确版本
app-server 与 WebSocket 代理，DSH 使用 root-owned 原生 guard、真实 Tool 定义身份核对及
受控启动器。普通 Skill 安装、受控入口测试、当前桌面日常接管是三项不同验收。
此预览仅支持配置好的本地来源及两类当前产物验证器；公共检索、任意脚本沙箱和必须修改 Skill
的通用验收能力尚未接通时明确拒绝，不能把某个 JSON 用例通过说成所有专业任务均已覆盖。

阶段状态机证明的是已纳管操作不能越过已定义前置检查。它不自动判断艺术审美、事实真伪或所有未来任务的正确性。没有接入宿主时，严格无跳步验收仍未通过，不能隐去这一差别。

## 日常入口与安装完整性的追加验收

受控测试入口通过后，还须逐项验证普通入口，不能把两者合并计数：

- 使用真实新会话、两个并发会话、同会话新任务及冷启动恢复；保留原始用户授权，旧正文回执不能重放。恢复时无法可靠还原证明状态，就重新核本次事实，不能从模型历史恢复“已通过”。
- 在宿主真正的连接/调度入口阻断未知路径。局部 WebSocket 配置不证明云端、SSH、WSL、子代理或其他驱动已覆盖。未接入的入口须在连接或调用前拒绝，不能只写禁止指令。
- 先核发行源码，再核安装后的完整依赖树，最后才导入第三方代码或启动模型。锁文件的下载摘要不能检测安装后篡改；首次信任须来自真实受控安装或独立认证的原始包。安装器自身的入口、内部模块和依赖也须核实，不能只哈希一个入口文件。
- 参数路径与实际文件身份分别检查。Windows 大小写、尾点/尾空格、短名、符号链接和既有硬链接可能指向同一文件；仅 `realpath` 或字符串目录名单不能证明私有状态不可读写。用当前主机的真实反例验证，副作用应为零。
- 原生工具名称相同不证明证据格式相同。持续终端混合文本不能冒充具有退出码、完整 stdout/stderr 和截断标记的结构化进程结果。缺必要结果字段就阻断该能力，不能剥终端文本拼一个成功回执。
- 安装路径须从真正的日常启动语境验证。MSIX 等宿主可能重定向 AppData；当前进程能读到的逻辑目录，不证明普通终端或桌面启动器能读到同一文件。默认配置用跨语境稳定的位置；复用依赖用已核验的规范物理路径，不复制大目录凑“安装成功”。

每次报告分别标出：作者已跑、他人独立复现、跳过、未覆盖及当前来源哈希。HMAC 或签名只能认证记录来源/一致性，不能把作者的真实模型声明变成第三方独立验证。

桌面宿主接入还须用用户实际项目验证正常初始化、目录选择、项目添加/信任、文件读取和冷启动保留；几个文字产物用例、协议替身或独立原生读取都不能代替这条界面链。冷启动后必须在原会话再提交一次实际工具任务，验证当前文件重读和门禁仍有效；仅显示历史记录或返回 ready 不算恢复执行通过。需要用户处理系统确认时，先把入口修到能真实发起，再明确交接该确认；未完成前不得宣称整套桌面可用。

正常宿主控制与模型工具分开核验：仅接精确所需接口及配置项，保留其余门禁。合法初始化可能异步改写受保护配置，界面重连也不证明原生后端已重启；应验证完整配置变化、真实完成通知、新后端状态，并复验并发任务、冷恢复及无关配置夹带的拒绝。

通用任务没有预先定义的语义验收器时，结构检查只能证明当前文件可读、语法或字节一致；原目标仍需实际用户对当前产物的反馈，或额外可信领域验收器。模型不得更换原目标、自己提供标准答案或把普通最终回复当交付通过。对话空闲与业务完成须由宿主分别呈现。

## 真实宿主输入与失败分类

流程控制须用真实编辑器或原生消息通道的序列化输入测试。选择、接受等单条控制命令可在
**识别副本**上去除首尾空白；原始授权、反馈及审计仍保留原文。不能只取第一行、折叠内部
换行或提取某个命令片段：含额外文字、第二条命令或未知方案 ID 的消息不能取得选择或验收
权限。合法 LF、CRLF、外围空格与这些相邻拒绝例须同时验证，不能只测手写的无换行字符串。

恢复流程也不能靠把所有异常降为普通拒绝实现。可信边界可在调用前拒绝明确的参数或能力
不匹配，例如把 Markdown 正文当成仅支持 Python 的可执行方法；拒绝不得调用执行器、签发
执行回执或写产物，并应允许按当前阶段纠正。来源暂时不可取得与既有缓存被篡改须分开分类；
实际执行器、collector、完整性或未知异常仍阻断。异常自报的名称、错误码或 `business=true`
不是可信分类依据。关闭订阅、清理和退出不得覆盖最先观察到的失败原因。

“新目标不存在”可纠正，不代表已保护输入或已验证产物消失也可继续。完整性检查内部的
路径拒绝不得复用调用参数错误的降级；须覆盖检查前、异步读取返回后到实际使用之间的
消失、类型/链接及字节变化。先前检查通过不能替代当前实际读取的身份与内容核对。

新增完整性判据须同时验证真实原生宿主的正常路径与攻击邻例。时间戳变化本身不等于
内容损坏；若正常宿主操作也会改变元数据，先实测具体字段，再在同一受控权限通道
确认身份和字节，不得以替身执行器通过代替原生正例，也不得添加绕过权限的直接读回。

默认命令验收须逐段读回实际转发链及当前来源版本，再从新终端或真实快捷方式运行。
PATH 首项正确或显式测试入口成功，不证明它转发的日常入口已完成升级。

同一会话 ID 不证明跨回合仍是同一个原生 Agent，也不证明其读取观察或权限缓存保留。
写入适配须实测新 Agent 对已有文件的修改：宿主原始字节读取不自动建立原生写入器的
读取观察。补登记仍须经过原权限通道，且不得先刷新旧基线来掩盖外部改动；原生的
“自上次观察后已变化”检查继续有效。

## 行为回归

真实模型测试先按完整任务的来源体积、必要往返、上下文重复发送及反馈闭环估算预算，并留出正常修正余量。用户已授权完整验证时，不得自设很小的调用数、时限或累计输入上限，反复截断正常流程再重跑。保留异常失控保护，任务达到验收就停止；不能为省预算跳过来源、选择或反馈，也不能无界重试。计量必须区分消息 JSON 的 UTF-8 字节、提供商报告的输入/缓存/输出 token 与费用，不能混称。预算拒绝须在调用前记录实际量、上限和明确原因；报告真实原生回合的终止原因，不能把取消或预算中止写成模型没完成产物。复测前先用本地脚本覆盖临界值、慢回合及异常终止，确认不是测试器自身截断。

独立评分器也要先校准：用满足用户原始要求、但采用不同合法表达或布局的样本检验，另加缺事实、乱码、关键词拼凑等失败邻例。评分器不得夹带用户未要求的固定标题、措辞或布局。发生“产物看似正确但评分失败”时，保留原失败，逐条核原目标与实际字节后修正评分器或产物；不能直接降低事实、完整性和反馈要求，也不能把评分器错误归给模型。

反例测试必须实际观测并断言触发前提已成立；系统调用返回成功不证明状态已经改变。对时间戳、权限、缓存或身份等边界，用有界操作制造可观测差异，并在被测处理器之外独立核对夹具确实触发。否则夹具断言异常可能被处理器捕获成预期失败，造成假通过；无法制造前提应报夹具失败，不改期望、不跳过。

调用请求只是尝试。产物核验须按真实调用身份关联成功返回和当前文件；后续被拒绝的写入
不能替换先前实际成功的产物证据，也不能让独立验收驱动因解析这个失败请求而误杀仍可纠正的会话。

单次回复额度按用户明确上限及当前官方模型、本机 SDK 的真实参数能力设置，不能沿用很小的旧常量。原生 `max-tokens` 等可恢复终止与业务状态分开检查：保留真实终止原因，按已产生的当前方案、产物和阶段继续独立校验；未就绪时在同一会话续答取证。截断既不能冒充验收通过，也不应自动丢弃已经完成的全部工作。真实权限拒绝、暂停、保护输入损坏等失败仍须阻断，不能借恢复绕过。

探针显式传入额度，不证明日常入口也应用了同一上限。核实际提供商调用前的有效值，
同时验证未指定值、UI/SDK 请求更高值和明确更低值；不能只核配置文件或测试器参数。
