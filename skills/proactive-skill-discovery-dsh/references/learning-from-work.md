# 从实际任务沉淀 Skill

每个执行任务结束或交接前读取并给出经验处理结果；发现非显然有效方法、可复用工具、技能缺漏或失败反例时完成对应维护，不等用户纠错。总结应减少未来同类错误，不以新增文件数量衡量成果，也不每个任务都创建新 Skill。

这里的学习是维护可检索、可执行且可重验的流程资料，不是更新模型参数，也不保证宿主自动读取或以后永不出错。保留简短、适用的经验；更多规则并不必然更好。

## 从证据到可执行经验

1. **核对事实。** 找到实际触发条件、错误表现、原因、有效修正及验证产物。区分亲自观察、工具/外部模型返回和推测；无法复现的建议标为待验证，不写成已证实流程。一次失败也可能暴露重要机制，但不能仅因一次网络超时就固化重试规则。
2. **提炼决策。** 写清“何时用、怎样判断、采取什么动作、如何验证、何时不适用”。提炼导致成功的方法，不复制整段对话、临时进度或事后叙事。
3. **选择归属。** 先查已有技能：同一能力的缺漏直接修订；上游技能保留来源/许可，用适配层或许可允许的分叉承接；没有合适归属且方法能跨任务复用才新建。项目特有审美、路径和暂停点留在项目配置；凭据、私有素材和原始日志不进入共享包。
4. **完成维护。** 可用时采用宿主的 skill-creator 或等效创作流程。主体只放触发、关键决策和验证标准；较长细节放 references/，重复且确定性的操作才加 scripts/。保留现有调用策略和无关能力，避免重复技能或互相递归调用。
5. **验证实际决策。** 修改前留存原版与真实失败证据，或用现实情景检查基线；修改后用同类任务及一个相邻反例验证。检查它既能纠正目标问题，也不会把项目偏好扩散到其他任务。执行结构/引用检查，有代码则跑真实输入。基线本来正确时如实记录，不能声称测出了提升；未完成行为验证时明确验证范围，不能宣称已证明有效。
6. **记录并交付。** 在最终答复或已有交付文件中明确给出：经验及事实依据、实际修改的 Skill 文件与段落、修改内容、同类行为验证及相邻反例结果、遗留限制。不能只说写了日志、以后会注意或已经总结。已验证且授权范围内应维护的内容，实际修改并部署到可发现的个人目录；不能停留在建议。仅在已有发布授权覆盖本次变更时同步公开仓库，发布前去除私人信息并核对许可证。总结或维护 Skill 不授权发送消息、执行付费操作或恢复暂停任务。

## 每次交付必须选择并交代的结果

| 证据状态 | 处理及交付内容 |
| --- | --- |
| 已验证的方法或明确可识别的失败机制 | 实际更新最合适的已有 Skill；无合适归属才新建。给出位置、具体规则及验证产物 |
| 用户明确提出的通用工作要求 | 接入对应 Skill 的启动条件、具体行动及必填交付，验证新的决策；不等再次失败才采纳。将具体项目偏好与事实留在项目 |
| 有失败事实，原因/修法待验证 | 保存反例、未证实部分与下一验证动作；不能说已验证或已完成维护 |
| 本次没有可复用增量 | 说明检查了哪些实际结果、已有哪条方法覆盖以及为何无需修改；不空写“无经验” |
| 停止或写入限制生效 | 交代已完成/未完成和证据位置，遵守限制；不为总结恢复原任务 |

上表是必须交代的处理结果，不是允许跳过核查的标签。重复问题已有一般提醒却仍发生时，需查能改变判断或执行的方法，用真实反例验证，不能继续加“认真、完整、仔细”冒充经验维护。

例如：多个导出任务误看旧预览，而实际验证源修订与预览对应后有效，应补强现有导出审核 Skill 的产物对应检查；“此项目偏好绿色”仍留在项目配置。不能只保存“下次认真看”这类没有判定方法的提醒。

## 经验的晋升与纠错

**发生过的事实、解释和可执行规则分开。** 操作失败后重试成功，只证明本次恢复，不证明重试是修复机制，更不能推出所有同类操作都必须重试。把未核原因留作候选；有可复现的失败→修正→复验依据时，才形成带触发、动作、判据及不适用范围的规则。单次失败揭示的明确机制可以保留，不能冒充多任务普遍有效。

规则晋升前保留旧版和失败证据，用未参与写规则的新任务实际执行，再测一个不该触发的相邻任务。分别评估是否识别问题、是否匹配并用上能力、产物是否正确、是否恰当地维护经验；只改对文档或通过结构校验不证明后面几项。能隔离比较时固定任务、输入、宿主及版本；两边都正确就记平局，有反例就修订/撤回候选规则后重测，不包装成提升。

复用时重新核当前适用条件。来源/依赖/项目要求改变、结果矛盾或同类失误复发时，检查原依据和代表性行为；不是只重读旧“已通过”。仅测单项成功不能撤销原来针对并行场景的保护规则。查证失败应记录本次未能验证及下一动作，不能刷新成成功验证。过时的是某条适用推断，不是历史事实；规则长时间未用也不自动证明错误，更不能据此删掉仍有效的用户要求。

修订后仍恶化或不适用时，恢复/收窄实际生效的规则，保留原事件、反例与版本来源，避免下次再次学习同一个错误结论。只把已核的一般方法写入通用 Skill；数据格式、具体审美和单项目状态留在相应领域/项目记录。事实已在权威源维护时保存定位及失败处理方法，不再抄一份容易过时的常量。
